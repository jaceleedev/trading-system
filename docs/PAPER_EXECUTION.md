# 전향적 모의 매매

모의 매매는 저장한 판단과 자금 계획을 선택한 뒤에 관측된 시장 자료로 체결 가정을 검토하는 별도 원장입니다. 실제 계좌 보유량, 현금, 주문 상태나 계획 예산의 배정을 바꾸지 않습니다. 모의 체결과 손익은 실제 주문·체결 실적이 아닙니다.

## 화면에서 진행하는 순서

1. 상단에서 시작 기준이 될 계좌 관측을 명시적으로 선택합니다. 관측의 보유 종목과 시각을 확인한 뒤 모의 원장 이름과 통화별 초기 모의 현금을 직접 입력합니다. 매수 가능 금액은 현금 잔고가 아니므로 자동으로 복제하지 않습니다. KRW와 USD는 각각 입력하고 평가하며 환산 없이 합산하지 않습니다.
2. 모의 원장을 선택하고 저장된 자금 계획에서 하나의 대안을 고릅니다. 묶음 안의 매수·추가 매수·유지·축소·매도와 수량을 확인하고 체결 가정을 제출 전에 고정합니다. 대안 선택 시점이 이후 관측을 구분하는 기준이 됩니다.
3. 이후 저장된 분봉 캡처를 선택해 모의 원장을 진행합니다. 캡처를 선택하는 행위는 새 시장 자료를 수집하는 행위와 다릅니다. 서버는 대안 선택 이후의 관측인지와 캡처 계약을 확인한 뒤 고정된 가정을 적용합니다.
4. 미체결, 부분 체결, 완료 상태와 비용, 통화별 현금·보유 평가를 확인합니다. 남은 주문의 취소는 모의 원장에만 기록합니다. 체결 내역과 평가에 사용한 관측 시각을 함께 확인합니다.

원장을 만드는 데 사용한 계좌 관측과 현재 화면에서 선택한 계좌 관측은 따로 표시합니다. 기존 원장은 이후 계좌 선택만으로 다른 계좌를 기반으로 다시 만들어지지 않습니다. 매매 방향이나 시장, 종목 규모, 보유 기간을 화면에서 하나의 전략으로 제한하지 않습니다.

## 처리 결과를 확인하지 못했을 때

저장이나 진행 요청의 응답을 받지 못하면 같은 요청으로 결과를 다시 확인합니다. 결과를 확인하기 전에 다른 요청으로 복제하지 않습니다. 최신 원장과 변경 순서가 맞지 않으면 다시 조회한 뒤 현재 상태를 기준으로 작업합니다. 조회 중이거나 조회가 실패한 화면은 이전 결과를 최신 결과처럼 표시하지 않습니다.

작업 저장 기능이 꺼진 작업실에서도 기존 계좌·조사 자료를 읽을 수 있습니다. 모의 원장은 별도 저장 기능이 켜진 작업실에서 사용합니다. 합성 작업실의 기록은 합성으로 표시하며 실제 투자 성과와 구분합니다.

## 최초 체결 가정

`next_observed_minute_close_v1`은 비수정 1분봉의 종가를 기준으로 합니다. 대안 접수
시각 이후에 시작한 봉만 체결에 사용하고, 종료·조회·로컬 접수 시각 순서를 검사합니다.
같은 봉의 재조회나 수정값으로 거래량을 다시 쓰거나 기존 체결가를 바꾸지 않습니다.
늦게 도착한 더 오래된 봉으로 원장을 되감지 않습니다. 일봉과 수정주가는 이 프로필의
체결 입력으로 사용하지 않습니다. 이는 최초의 모의체결 모델이며 AI 재판단 빈도나
포지션 보유 기간을 정하는 제약이 아닙니다.

가격 차이(`slippage_bps`), 거래량 참여율(`participation_bps`), 수량 단위
(`quantity_step`)를 제출 전에 명시합니다. 매수 가격은 기준보다 높이고 매도 가격은
낮추는 방향으로 차이를 반영합니다. 같은 봉의 거래량은 접수 순서에 따라 공유합니다.
한 대안은 최대 20개 항목이며 거래 수량은 지정 단위의 배수여야 합니다.
체결마다 거래금액 비례 비용을 계산하고 고정 수수료는 항목의 첫 체결에 한 번만 냅니다.

거래 항목에는 양수인 가정 가격이 필요합니다. 예상 가격에 위 차이와 비용을 적용한
자금 상한을 먼저 배정합니다. 실제 모의 기준 가격이 높아져도 그 항목에 배정된 돈을
넘어 쓰지 않으며, 부분체결·미체결로 남을 수 있습니다. 매도할 수량도 다른 미체결
계획에 중복 배정하지 않습니다. 매각 대금은 모의체결 후 원장에 들어오고, 앞서 접수한
매수의 자금 상한을 자동으로 늘리지 않습니다.

초기 현금을 명시하지 않은 통화는 미확인으로 유지합니다. 그 통화의 기존 보유를
관측 기준으로 표시할 수 있지만 거래하려면 해당 통화의 초기 모의 현금도 명시해야 합니다.
모의 현금 잔고와 아직 체결되지 않은 항목의 잔여 자금 배정을 구분합니다.

## 결과와 자료 범위

체결 이벤트는 사용한 캡처·봉·관측 버전 ID, 기준 종가, 가정 체결가, 수량·비용,
봉 종료 시각과 로컬 기록 시각을 보존합니다. 원장의 손익은 초기 보유의 관측 원가를
포함할 수 있으며 이번 AI 판단 이후의 수익을 뜻하지 않습니다. 취득원가나 평가 가격이
없으면 관련 손익·평가액은 미확인이고, 확인한 실현손익과 원가 미확인 매도 건수를 나눕니다.
모의체결 비용과 원가에 따른 평가도 정확한 소수 문자열로 제공합니다. 정밀도 256자리의
계산에서 반올림이 생기면 표시합니다.

입력은 선택해 접수한 자료의 범위에 한정됩니다. ‘시장 전체의 다음 봉’, 완전한 거래량·
호가·대기열·시장 충격이나 실제 체결 가능성을 확인한 것이 아닙니다. 캡처의 조회 시각은
저장된 출처 선언이고 DB 접수 시각은 작업실의 관측 기록입니다. 해시와 접수 기록이
공급자 진실성·봉 최종 확정·모델이 당시 가진 지식을 인증하지 않습니다.

## CLI·저장·복구

웹은 `--jobs`를 사용해 실행합니다. CLI도 같은 로컬 DB와 서비스를 사용합니다.

```bash
uv run trading paper create --workspace /path/to/workspace --input book.json
uv run trading paper list --workspace /path/to/workspace
uv run trading paper submit --workspace /path/to/workspace --id <BOOK_ID> --input intent.json
uv run trading paper advance --workspace /path/to/workspace --id <BOOK_ID> --input observations.json
uv run trading paper cancel --workspace /path/to/workspace --id <BOOK_ID> --intent-id <INTENT_ID> --input cancel.json
uv run trading paper show --workspace /path/to/workspace --id <BOOK_ID>
```

합성 작업실에서는 `--synthetic`을 명시합니다. 일반 작업실에서 합성 원장을 만들거나
진행할 수 없습니다. 입력 타입은 생성 OpenAPI의 `PaperBookCreate`, `PaperSubmit`,
`PaperAdvance`, `PaperCancel`을 따릅니다. 원장 선택과 대안 선택에는 서버 시각을 사용하고
HTTP 요청으로 과거 시각을 공급할 수 없습니다.

원장·선택·관측 접수·체결·취소는 PostgreSQL의 별도 `paper_*` 테이블에 기록합니다.
원장 행을 잠가 상태 변경과 이벤트를 함께 커밋합니다. 같은 요청 키는 원래 응답을
반환하고, 새 변경은 현재 버전을 요구합니다. 복구에는 [DB 백업](LOCAL_BACKUP.md)과
원본 계좌·계획·시장 자료의 [파일 백업](ARTIFACT_BACKUP.md)이 모두 필요합니다.
파일 백업만으로 모의 원장이 복원되지는 않습니다.

초기 로컬 구현은 원장당 선택 100개·활성 선택 20개, 요청당 캡처 20개·봉 200개까지
처리합니다. 한도를 넘으면 묵시적으로 생략하지 않고 거부합니다. 상세에는 최근 선택과
이벤트 각 100개 및 생략 수가 포함되고, 이벤트는 순번으로 다음 페이지를 읽을 수 있습니다.
한 원장의 한도를 넘는 새 실험은 명시적인 새 원장으로 시작합니다.
