# 자동 트레이딩 연구실

월 50만 원의 개인 투자금을 대상으로, 사람이 계속 화면을 보지 않아도 운용할 수 있는 시스템을 검증하는 첫 버전입니다. 연금저축 월 50만 원과 기존 개인 자산은 이 프로젝트의 대상이 아닙니다.

현재 상태는 **실행 가능한 연구 / 로컬 모의매매 프로토타입**입니다. 실제 주문 기능과 계좌 연결은 없으며, 초과수익이 검증된 전략도 아직 없습니다. 공개 시세를 읽는 기능과 실제 돈으로 거래하는 기능을 혼동하지 않아야 합니다.

## 실행

Python 3.11 이상, 외부 패키지 없이 실행합니다. 프로젝트 폴더에서:

```sh
python3 -m unittest discover -s tests -v
python3 -m trading_system demo --output data/demo.csv
python3 -m trading_system backtest --csv data/demo.csv --data-kind synthetic --config configs/research.toml --output reports/demo
```

`reports/demo/index.html`은 독립적으로 열 수 있는 보고서이고, `result.json`에 전체 계산 경로가 기록됩니다. 합성 데이터의 수익률은 전략 수익성의 증거가 아닙니다.

시장 선택 전에도 공통 CSV 형식으로 연구할 수 있습니다. 공개 데이터 연결 예제로 Upbit 일봉 어댑터를 제공합니다. 아래 예제는 거래소나 투자 종목의 추천을 의미하지 않습니다.

```sh
python3 -m trading_system fetch --market KRW-BTC --bars 500 --output data/krw-btc.csv
python3 -m trading_system backtest --csv data/krw-btc.csv --data-kind historical --config configs/research.toml --initial-cash 500000 --monthly-contribution 500000 --output reports/krw-btc
```

## 자동 모의 운용

한 번 실행해 상태와 모의 체결을 저장합니다. API 키가 필요하지 않습니다.

```sh
python3 -m trading_system paper --market KRW-BTC --config configs/research.toml --db data/krw-btc-paper.sqlite
python3 -m trading_system status --db data/krw-btc-paper.sqlite
```

지속적인 로컬 실행은 사용자가 다음 명령을 실행할 때만 시작됩니다.

```sh
python3 -m trading_system paper --market KRW-BTC --config configs/research.toml --db data/krw-btc-paper.sqlite --watch --interval 60
```

`Ctrl-C`로 끝납니다. 프로그램과 컴퓨터가 실행 중일 때만 동작하며, 서버 배포나 절전 방지는 설정하지 않습니다. 정상 상황에서 완료된 일봉이 새로 생길 때 신호를 평가하고, 매 polling 때 현재 시세로 손실 중단 조건을 확인합니다. 모의 체결은 실행 시점에 관측한 가격에 비용을 더해 계산합니다. 과거 시가로 뒤늦게 체결시키지 않습니다.

신규 신호에는 UTC 기준 어제의 완결 일봉과 그 봉이 끝난 이후의 시세가 필요합니다. 오래된 일봉이면 신규 신호는 차단하고 기존 포지션의 현재가 평가·손실 중단은 계속합니다. 차단 이유는 `signal_blocked_reason`에 남습니다.

모의계좌의 최초 자금은 50만 원입니다. 이 버전의 지속 모의계좌에는 추가 입금 기능이 없고, 월 50만 원의 추가납입은 **백테스트에서만** 시뮬레이션합니다. 재시작 때 `--initial-cash`로 기존 계좌를 증액할 수 없습니다. 시장이나 설정을 바꿔 비교하려면 별도의 DB 파일을 지정합니다. 실제 주문/입금/출금 명령은 없습니다.

## 첫 기준 전략과 계산 전제

- 과거 20일 단순이동평균이 60일 평균보다 높으면 설정된 비중으로 현물 매수하고, 그렇지 않으면 현금으로 대기합니다. 전략의 수익성을 주장하는 설정이 아닙니다.
- 백테스트에서는 직전 완료봉까지만 신호를 계산하고 다음 봉 시가에 체결합니다. 현물 매수/매도만 지원하고 차입·공매도는 모델링하지 않습니다.
- 같은 비중 신호가 유지되면 매일 재조정하지 않습니다. 그동안 들어온 추가 입금도 다음 비중 변경 때까지 현금으로 대기합니다.
- 수수료 5bp, 체결 불리함 10bp, 투자비중 80%, 손실 중단 15%, 최소 주문 5,000원은 `configs/research.toml`에 있는 **연구용 가정**입니다. 계좌의 확정 수수료나 사용자가 승인한 실거래 위험 한도가 아닙니다.
- 추가 입금은 첫 관측월 이후 월이 바뀐 첫 봉에 한 번 반영합니다. 관측되지 않은 달을 소급해 채우지 않습니다. 초기 50만 원과 이후 월별 50만 원은 별도입니다.
- 납입 직전 평가액을 기준으로 유닛을 발행해 수익률과 최대 낙폭에서 추가 입금 효과를 제거합니다. 계좌 잔액 증가를 투자 수익으로 표시하지 않습니다.
- 비교 기준은 같은 초기금·월 입금·비용으로 첫 봉과 추가 입금 때 현금을 전액 매수하는 적립식 보유입니다. 비교 기준에는 SMA·80% 비중·손실 중단을 적용하지 않으며, 서로 다른 위험 노출을 가진 두 결과로 읽어야 합니다.
- 백테스트 손실 중단은 종가에서 감지한 뒤 다음 봉 시가에 청산합니다. 모의 운용은 관측 시점의 시세에서 감지합니다. 가격 급변·지연·거래 정지·최소 주문 제약 때문에 설정 수치보다 더 손실 날 수 있습니다. 중단은 자동 해제되지 않습니다.
- OHLCV만으로 호가 스프레드, 유동성, 주문 대기열, 시장 충격, 부분 체결을 재현할 수 없습니다. 현물 주식 연구에 쓰려면 분할·배당·거래일·상장폐지·통화 처리도 추가해야 합니다. 현재 공개 시세 어댑터와 모의 운용은 가상자산 UTC 일봉에 한정됩니다.
- 세금·물가·서버 비용은 계산하지 않습니다. 정확한 총자산 변화는 별도 비용까지 반영해야 합니다.

## CSV 형식

```csv
timestamp,open,high,low,close,volume
2025-01-01T00:00:00+00:00,100,110,90,105,12
```

`timestamp`는 봉 시작 시각이며 시간대가 필수입니다. 가격은 유한한 양수, 거래량은 유한한 0 이상이어야 합니다. 순서 역전·중복·OHLC 범위 오류는 거절합니다. Upbit는 거래가 없는 날의 봉을 제공하지 않을 수 있습니다. 누락 봉을 임의의 가격으로 만들어 넣지 않으며 SMA의 기간은 실제 관측 봉 수입니다.

## 수익성 연구의 다음 단계

1. 거래 시장·계좌·상품 범위와 감당할 계좌 손실을 정합니다. 기존 개인 총자산 정보는 필요하지 않습니다.
2. 선택한 시장에서 충분한 기간과 다양한 장세의 데이터를 확보하고 오류와 비용을 점검합니다.
3. 기준 전략과 사전에 정한 소수의 전략 가설을 비교합니다. 모든 시도와 설정을 기록합니다.
4. 개발 구간, 검증 구간, 마지막 평가 구간을 시간 순서로 분리합니다. 마지막 구간을 보고 바꾼 전략에는 새 평가가 필요합니다. **현재 보고서는 이 절차를 마친 결과가 아닙니다.**
5. 비용 증가·불리한 체결·급락·데이터 단절을 시험하고, 같은 기간·자금 흐름의 비교 기준과 평가합니다.
6. 모의 운용으로 주문 기록, 재시작, 신호 시각, 손실 중단을 검증합니다. 기대수익은 별도로 검증합니다. 실거래 연결은 구체적인 주문 범위와 위험 설정을 확정한 뒤 진행할 후속 작업입니다.

성과표에는 비용 후 수익, 납입금과 구분한 수익률, 최대 낙폭, 거래 수, 비교 기준, 운용 오류를 함께 남깁니다. 승률이나 특정 기간의 높은 수익률 하나로 전략을 채택하지 않습니다.

## 공식 참고 자료

- [Upbit 일봉 API](https://docs.upbit.com/kr/reference/list-candles-days): 완료 봉 처리, 페이지당 최대 200개, 거래 없는 구간의 누락.
- [Upbit 현재가 API](https://docs.upbit.com/kr/reference/list-tickers): 읽기 전용 시세 스냅샷.
- [Alpaca paper trading](https://docs.alpaca.markets/us/docs/paper-trading): 모의 체결과 실거래 사이의 시장 충격·지연·주문 대기열 차이. 이 프로젝트가 Alpaca에 연결된다는 뜻은 아닙니다.
