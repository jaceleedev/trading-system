# 웹 계좌·시장 관측 수집 (기능 28)

웹의 새 관측 수집은 사용자가 정한 GET 조회를 기존 PostgreSQL 작업에 접수한다.
‘저장 자료 다시 읽기’는 기존 파일을 읽는 동작이며 새 토스 조회를 접수하지 않는다.
수집에는 `--jobs` API와 같은 workspace의 `--allow-network` worker가 필요하다.
접수·복구·완료 자료 조회는 worker의 권한을 바꾸거나 주문을 생성하지 않는다.

## 계좌 선택과 처음 연결

웹 선택지는 검증된 **저장 계좌 관측**에 근거한다. 현재 토스에서 조회 가능한 계좌
목록이라고 표시하지 않으며, 계좌를 기본 선택하지 않는다. 선택한 관측 ID와 십진
문자열 `account_seq`를 요청에 함께 고정한다. 서버와 worker는 두 값의 일치를
검증한다. worker는 실제 수집의 첫 계좌 목록 응답에서도 선택 계좌의 존재를 확인한다.
계좌번호·토큰·원응답은 웹 응답에 포함하지 않는다.

저장 관측이 없는 계좌의 첫 연결은 [TOSS_ACCOUNT.md](TOSS_ACCOUNT.md)의
`trading toss-account list`와 명시적 `sync --account`를 사용한다. 이 CLI는 직접
네트워크·자격증명 경로이며 worker 권한 관측과 별개다. 웹 API는 선택지 제공을 위해
직접 계좌 목록이나 자격증명을 조회하지 않는다.

계좌 수집은 기존 필수 6개 조회 묶음이다. 계좌 목록, 국내·미국 보유 주식,
KRW·USD 매수 가능 금액, 수수료, 지원되는 OPEN 주문을 순차 조회한다. 부분 묶음을
완성 계좌로 만들지 않는다. 원자적인 한 시점의 상태가 아니며 전체 자산·모든 주문·
실제 현금 잔고를 확인하지 않는다. 금액의 소수 문자열과 미확인 값, 통화 구분을 유지한다.

## 시장 조회 범위

선택지는 패키지에 고정한 기존 시장 GET 계약에서 만든다. 임의 URL·endpoint·경로를
받지 않는다. 봉, 종목 정보, 시장별 종목 목록, 환율, 한국·미국 시장 달력을 제공한다.
종목·통화·시장·기준 시각·날짜 등 해당 endpoint의 입력을 명시한다. 봉은 `1m`/`1d`,
수정주가 여부, 페이지당 1~200개와 최대 1~10페이지를 지정한다. 다른 endpoint는
1회 조회다. `before`는 시간대가 있는 조회 기준이며 선택한 기간 전체 확보의 보장이 아니다.

완료 페이지에 다음 커서가 남으면 페이지 한도에서 잘린 결과다. `nextBefore` 필드가
누락되거나 유효하지 않으면 후속 범위를 미확인으로 남긴다. 명시적 `null`은 해당
조회 방향의 추가 페이지가 없다는 응답이며 전체 기간의 완결성을 보장하지 않는다. 단순 원응답 저장 성공을
차트 지원·데이터 완결성·확정 봉·최신 가격으로 바꾸지 않는다.

## API 경로

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/observation-captures/options` | DB·인증 없이 저장 계좌 근거와 고정 시장 입력 계약을 읽는다. |
| `POST /api/v1/observation-captures` | 명시한 계좌·시장 수집을 기존 작업에 접수한다. |
| `POST /api/v1/observation-captures/recover` | 원래 key와 입력으로 기존 작업을 읽기만 한다. 접수나 임대 복구를 하지 않는다. |
| `GET /api/v1/observation-captures/{id}/result` | 완료 작업의 실제 원본 ID·조회 범위·시각을 검증해 읽는다. |

## 응답 유실과 완료 결과

브라우저는 첫 접수 전에 workspace별 요청 영수증에 원래 request key와 입력을 보관한다.
새로고침 후에는 이 입력으로 기존 작업을 조회하며 자동으로 새 접수를 만들지 않는다.
명시적 재접수도 원래 키와 입력을 유지한다. 같은 키에 다른 입력은 거절한다.
저장된 브라우저 영수증은 복구 힌트이며 서버의 작업·원본 검증을 대신하지 않는다.

접수 확인 전, 대기, 실행, 실패, 취소, 완료를 구분한다. 작업 ID와 시도 시각은
수집 원본의 관측 시각과 별개다. 완료 결과는 작업이 실제로 만든 원본을 다시 읽어
ID·내용·계좌·endpoint·query 연결을 검증한다. 자료가 없거나 일치하지 않으면 연결을
제공하지 않는다. 실패 중 저장된 부분 원본을 완료된 관측으로 내보내지 않는다.

상태 자동 재조회는 기능 27과 같은 가시성·최대 5분·오류 정지 경계를 따른다.
상태 확인과 완료 원본 조회는 읽기 전용이다. worker 중단 후 재시도는 기존 작업
임대 계약을 따르며 외부 조회의 정확히 한 번 실행을 보장하지 않는다.

## 다음 입력으로 명시적 연결

완료 계좌 관측은 사용자가 버튼을 눌러 다음 조사 입력으로 선택한다. 완료 시장
관측은 다음 조사 또는 모의 진행의 후보로 전달한다. 다른 계좌로 전환한 뒤 늦게
도착한 결과는 현재 선택에 자동 적용하지 않는다. 과거 조사 revision이나 고정된
모의 대안·가격·비용 가정을 교체하지 않는다.

수정하지 않은 지원 `1m` 관측은 모의 입력 후보일 뿐이다. 실제 모의 진행에는
선택한 원장·종목·통화·고정 선택 이후 봉·로컬 관측 영수증·수정 이력·거래량 등을
기존 모의 엔진이 다시 검증한다. 입력 전달 버튼은 모의 진행이나 체결을 실행하지
않으며 별도의 기존 ‘관측으로 진행’ 동작이 필요하다.

새 migration이나 운영 서비스 설치는 필요하지 않다. 검증과 실제 제약은
[HANDOFF.md](HANDOFF.md)의 기능 28 기록을 따른다.
