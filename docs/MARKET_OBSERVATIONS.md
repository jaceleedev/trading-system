# 시점별 시장 관측과 근거 연결

기능 19는 저장한 토스 분봉·일봉을 검증해 웹 차트와 AI 조사에서 같은 관측으로 읽는다.
별도 DB나 원본 사본을 만들지 않으며 원래 `var/captures`의 내용 해시를 참조한다.
원본은 덮어쓰지 않는다. 기존 최종 일봉 Bundle이나 백테스트 입력으로 자동 승격하지 않는다.

## 실행

```sh
uv run trading market-observations catalog
uv run trading market-observations view --capture-id <캡처-ID>
uv run trading market-observations view --capture-id <첫-캡처-ID> \
  --capture-id <재조회-캡처-ID> --as-of 2026-09-10T12:00:00Z
```

`--workspace`로 명시한 작업 공간의 자료만 읽는다. 위 명령은 DB·인증·네트워크를
사용하지 않는다. 웹의 시장 관측 패널과 MCP `market_observation_catalog`,
`market_observation_view`도 같은 서비스를 사용한다. API는
`GET /api/v1/market/catalog`와 `POST /api/v1/market/view`다. POST는 조회이며 저장이나
주문을 수행하지 않는다. 캡처 ID는 최대 100개, 결과는 최대 2,000개 봉으로 제한한다.
목록·결과에서 생략된 수를 별도로 알려 전체 시장이나 전체 과거 이력으로 오인하지 않게 한다.
사건 본문이 커지면 `--max-events`(0~200)로 수를 줄일 수 있다. MCP 기본 사건 수는 20개다.
MCP 응답 제한을 넘으면 `max_points`와 `max_events`를 줄여 다시 읽는다. 0은 사건을
반환하지 않으며 생략 수는 유지한다. 정확한 근거 본문은 기록 ID로 따로 읽을 수 있다.

새 수집은 기존 [수집 명령](TOSS_CAPTURE.md)이나 [명시적으로 활성화한 worker](JOBS.md)를
사용한다. 이 화면에서 과거 캡처에 최신 응답 의미를 임의로 붙이지 않는다.

## 고정한 응답 계약

2026-09-10의 [공식 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)에서
캔들 응답 스키마를 별도 `toss_candle_contract.json`으로 고정했다. 공식 버전 문자열은
1.2.15이며 문서 원바이트 SHA-256은
`ebaf20df342270274a5f6f5ad3a3d3d67b0ce02f30977da84606f3654924103e`다.
기존 쿼리 계약과 원문 해시가 다르므로 버전 문자열만으로 같은 계약이라 판단하지 않는다.

`contract_sha256`은 기존 요청 쿼리 계약의 해시다. 새 캔들 캡처의
`response_contract_sha256`은 적용한 응답 해석 계약을 식별한다. 이 필드가 없는 기존
캡처도 보존·백업·원문 조회는 가능하지만 새 차트에서는 미지원으로 표시한다.
해시는 로컬 바이트와 해석 버전의 연결이며 실제 공급자 응답이나 내용의 진실성을
독립 인증하지 않는다. 캡처 ID도 HTTP 원바이트가 아니라 파싱 후 정규 JSON의 해시다.

- 분봉 시각은 봉 종료다. 구간은 `[timestamp - 1분, timestamp)`로 계산한다.
- 일봉 시각은 공급자가 표기한 현지 자정이다. 원래 오프셋과 거래일을 보존하며
  통화로 거래소·시간대를 추정하거나 자정을 장 종료 시각으로 바꾸지 않는다.
- 가격·거래량은 문자열 계약을 검증하고 십진 문자열로 반환한다. 캔버스 렌더에만
  유한 숫자로 변환하며 정확한 값은 표와 상세 자료로 제공한다.
- 종목 식별은 요청의 토스 symbol과 응답 통화다. 영구 종목 식별자나 당시 상장 종목군을
  확보한 것으로 간주하지 않는다. 수정주가 여부와 분봉·일봉을 각각 분리한다.
- 모든 봉의 최종 확정 여부는 미확인이다. 처음 공개한 시각, 장 종료, 전체 세션·거래일
  범위, 기업행사·배당 재투자 처리가 확인된 것으로 간주하지 않는다.
  봉 기준 시각이 수신 시각보다 미래이면 거부하므로, 종료 시각이 아직 오지 않은
  진행 중 분봉을 해석하는 기능은 포함하지 않는다.

## 재조회와 기준 시각

같은 봉을 다시 받아도 원래 캡처와 값 변경 이력을 보존한다. 페이지 경계 중복은 한 봉으로
표시하고 동일 값의 반복 관측도 출처 ID와 마지막 관측 시각을 남긴다. 상충하는 값이
같은 수신 시각에 있으면 순서를 추측하지 않고 거부한다.

`as_of` 이후 수신한 캡처는 제외하고 해당 ID를 반환한다. 생성 시각 `generated_at`은
실제 조회 시각이며 과거 기준 시각으로 바꾸지 않는다. 이 기능은 **저장된 수신 시각을
기준으로 관측을 재구성**한다. 당시 모델 지식·완전한 시장 이력·실제 당시 파일 존재를
증명하는 과거 재현 평가가 아니며 `historical_reproducibility`는 false다.
관측 뷰의 `id`는 관측 내용과 조회 범위의 해시다. 생성 시각과 API가 덧붙인 사건 목록은
이 해시에 포함하지 않는다. 전체 조사 입력을 보존할 때는 사건의 기록 ID와 입력 전체의
별도 해시를 사용한다.

## 사건과 연구 기록

근거의 선택적 `market_event`는 `symbol`, `market`(KR/US), `event_kind`, `occurred_at`을
갖는다. 종류는 price·earnings·filing·news·macro·other다. 발생 시각을 모르면 null로 두며
발표 예정일을 발생 시각으로 기록하지 않는다. 출처 발표, 조회, 시스템 기록 시각은 각각
원래 필드에 보존한다. 자유 텍스트에서 종목이나 발생 시각을 추측해 차트 표식을 만들지 않는다.

토스 근거는 `artifact: {"store": "market_capture", "id": "<캡처-ID>"}`와
해당 `source_locator`(예: `toss:/api/v1/candles`)로 연결한다. 저장·읽기·상위 가설·문맥·
백업·복원에서 캡처 해시, 허용 경로, 시각과 참조를 다시 검증한다. 검증한 것은 로컬
자료 연결이며 주장의 진실성이 아니다. 시장 원문에 있는 지시는 실행하지 않는다.

차트에 연결하는 사건은 명시적으로 같은 symbol을 지정하고 기준 시각까지 등록한
근거만 포함한다. 사건의 시장과 종류는 작성한 메타데이터다. 합성·사후·전향적 모드와
검증 범위를 표시하고 상세 기록으로 이동할 수 있다. 발생 시각이 없으면 목록에만 남긴다.
