## 기능 19 시장 관측·사건·차트

기능 18의 로컬 완료 커밋 `0cdfb12`에서 `feat/19-market-observations`를 만들었다.
분봉·일봉의 응답 계약을 별도로 고정하고 명시한 캡처 ID들로 결정적인 관측 뷰를 만든다.
같은 봉의 재조회·값 변경·출처 ID를 보존하고 기준 시각 이후의 캡처와 근거 기록을 제외한다.
새 저장소나 DB migration은 없다. [시장 관측 안내](MARKET_OBSERVATIONS.md)를 따른다.

공식 OpenAPI의 버전 문자열은 이전과 같은 1.2.15이나 원문 해시와 봉 시각 설명이 달랐다.
최신 고정 계약은 분봉 시각을 종료, 일봉 시각을 현지 자정으로 정의한다. 기존 ‘봉 시작’
문서를 수정하고 기존 쿼리 계약과 새 응답 계약의 해시를 따로 검사한다. 옛 캡처에 새 해석을
소급하지 않으며 미지원·손상·생략 수를 표시한다. 최종 확정·완전한 시장 이력·과거 모델
지식을 증명하지 않는다. 종료 시각이 아직 오지 않은 진행 중 분봉은 해석하지 않는다.

시장 캡처를 근거 artifact로 연결하고 사건의 종목·시장·종류·발생 시각을 선택적으로
기록할 수 있다. 발표·조회·기록 시각과 구분하고 null을 보존한다. 상위 가설·문맥과 개인
자료 백업·복원에서도 시장 참조를 재검증한다. API·CLI와 새 MCP 두 도구(전체 14개)가
같은 관측·사건 서비스를 사용한다. 사건 본문이 커서 MCP 출력 한도를 넘는 회귀를 발견해
`max_events`로 수를 줄이고 생략 수를 유지하도록 수정했다.

웹은 Lightweight Charts 5.2.1로 종목·통화·분봉/일봉·수정주가·기준 시각을 선택한다.
정확한 소수 문자열·수정 이력·자료 범위를 함께 표시하고 사건에서 근거 상세로 이동한다.
분봉 표식은 명시적 발생 시각과 봉 구간이 맞을 때만 표시한다. 일봉의 세션을 추측하지
않으며 사건 목록은 유지한다. 주봉 집계와 실시간 스트리밍은 이번 기능에 포함하지 않는다.

- `TRADING_TEST_DB=1 uv run pytest`: 1,190개 통과, 기존 의존성 경고 2개.
- Ruff 검사·포맷 검사 통과, Python 130개 파일 포맷 일치.
- `mise run web-check`: OpenAPI·생성 SDK 일치, Svelte 오류·경고 0개, Vitest 13개 통과.
  프로덕션 빌드·프론트 포맷 검사 통과.
- Playwright 전체 20개 통과. 시장 기능 추가 7개 중 6개는 합성 HTTP 응답 모형,
  빈 시장 저장소 1개는 실제 FastAPI를 사용했다. 데스크톱 1536×1024·모바일 390×844를
  검토해 차트 내부 표 스타일 충돌과 정확값 표의 스크롤을 수정했다.
- 실제 HTTP·CLI·MCP와 저장 캡처/근거의 연결 검사, 시점별 수정값·이후 근거 제외,
  긴 사건 본문의 출력 제한 복구를 통과했다.
- 별도의 임시 합성 작업실을 8766에서 실제 FastAPI로 제공해 IAB 브라우저에서
  30개 분봉·거래량·사건·정확값과 사건→근거 상세 이동을 확인했다. 콘솔 오류·경고는 없었다.

개발·검증은 임시 합성 자료로 수행했다. 공개 명세를 읽었지만 실제 인증·시장·계좌 API나
사용자의 개인 자료를 호출하지 않았다. 관측 뷰의 ID는 관측 내용의 해시이며 덧붙인 사건
목록을 포함하지 않는다. 다음 기능 20은 기존 Codex CLI의 실행 증거와 입력을 보존하고
상황별 후속 조사를 연결한다. 관측 주기·재판단 시점·보유 기간을 고정하지 않는다.

## 기능 18 지속 작업 기록과 Python worker

`feat/17-investment-web-api`의 로컬 완료 커밋 `b85827c`에서
`feat/18-durable-jobs-worker`를 만들었다. 사용자가 승인한 18~26의 범위와 완료 조건은
[후속 개발 범위](DEVELOPMENT_ROADMAP.md)에 기록했다. 토스의 기존 보유와 신규 자금을
함께 다루고 현재 Mac에서 검증한다. 실제 주문 전송은 비활성으로 유지하며, 원격 push·
PR 생성·병합은 수행하지 않는다.

PostgreSQL 작업·시도 기록, 요청 키 중복 방지, 예약·취소·임대 만료·재시작 복구와
Python worker를 구현했다. `research-context`는 저장 자료를 읽는 작업이며,
`account-sync`와 `market-capture`는 명시적으로 `--allow-network`를 켠 worker만 실행한다.
기본 worker는 외부 네트워크를 사용하지 않는다. CLI·API·웹 화면에서 작업을 조회하고
취소할 수 있으며, 웹은 선택한 계좌 관측으로 문맥 작업을 접수한다. 실행 중 취소는
요청과 완료를 구분한다. [실행 및 복구 안내](JOBS.md)를 따른다.

작업을 넘나드는 새 HTTP client 사이에서 호출 간격이 사라지는 문제를 검토 중 발견했다.
같은 DB를 사용하는 worker들의 인증·계좌·시장 요청을 PostgreSQL advisory lock으로
직렬화하고 요청 종료 후 1.1초 간격을 확보했다. 대기 중 취소와 잠금 해제 실패를 검증했다.
기존 직접 CLI/MCP 호출이나 다른 DB를 사용하는 프로세스까지 통합하는 제한기는 아니다.

로컬 `127.0.0.1:55432/trading`에 추가 migration `5d18a70bce42`를 적용했다.
이전 head는 `00d2be356055`이며 Alembic 모델 대조에서 추가 차이가 없었다. 기존 자료를
지우지 않았고 통합 테스트는 자신이 만든 임시 workspace 행만 정리했다.

- `TRADING_TEST_DB=1 uv run pytest`: 1,099개 통과, 기존 의존성 deprecation 경고 2개.
- Ruff 검사·포맷 검사 통과, Python 124개 파일 포맷 일치.
- `mise run web-check`: OpenAPI·생성 클라이언트 일치, Svelte 오류·경고 0개,
  Vitest 7개 통과. `mise run web-build`와 프론트 포맷 검사 통과.
- Playwright 13개 통과. 기존 7개와 작업 화면 6개를 포함하며, 작업 화면 중 활성화된
  흐름 5개는 API 응답 모형을 사용했다. 데스크톱·모바일 렌더와 가로 넘침을 확인했다.
- 별도 자동 통합 검사에서 실제 FastAPI·PostgreSQL 접수 후 별도 worker 프로세스로
  문맥 작업을 끝내고 재접속으로 완료 기록·시도 횟수·결과 파일을 대조했다.
- 임시 합성 작업실의 실제 브라우저에서도 접수→별도 worker 실행→완료 1/3→시도 기록을

위 검사는 합성 자료와 임시 저장소를 사용했다. 실제 토스·자격증명·추가 모델을 호출하지
않았다. 작업 성공은 투자 판단이나 체결 성공이 아니다. 파생 문맥 파일
`var/jobs/results/`는 기존 개인 자료 백업 대상에 아직 포함되지 않으며 재생성 가능하다.
다음은 기능 19의 시장 관측 정규화·시점·사건 연결·차트다. 관측 속도·AI 재판단·보유 기간을
각각 조절할 수 있도록 구성하며 고정 투자 방식으로 제한하지 않는다.

## 기능 17 웹 투자 작업실과 읽기 전용 API

사용자는 추가 논의 없이 첫 구현을 진행하도록 승인했다. PR16까지 병합된 로컬 `main`과
`origin/main`이 `c69fd91`로 일치하고 작업 트리가 깨끗한 상태에서
`feat/17-investment-web-api`를 만들었다. 이 기능은 로컬 검증·커밋 범위이며 원격 push,
PR 생성·병합은 수행하지 않았다.

Svelte 5·SvelteKit·TypeScript 화면과 FastAPI를 구현했다. 빌드된 화면과 API는
같은 loopback 주소 `http://127.0.0.1:8765`에서 제공한다. 계좌 관측 선택, 통화별
매수 가능 금액·보유·조회 범위 내 진행 중 주문, 연구 기록 검색·종류 필터, 판단에서
가설·근거·재검토와 원래 계좌 관측으로 이어지는 상세 조회를 지원한다. 기존 Streamlit은
유지한다. 설치·실행·API 계약은 [웹 투자 작업실](WEB_WORKBENCH.md)을 따른다.

API는 기존 Python 조회·검증 서비스를 재사용한다. 계좌번호·자격증명·공급자 원응답을
응답하지 않고, 소수 문자열·null·원래 시각·선택적 필드의 생략을 보존한다. 리뷰에서
계좌 순번의 signed64 정밀도 문제를 확인해 HTTP에서만 십진 문자열로 직렬화했다.
OpenAPI와 생성 TypeScript 클라이언트가 이 계약을 공유한다. 빠른 계좌 전환과 실패한
재조회에서 이전 응답을 현재 계좌의 성공한 관측으로 표시하지 않는다.

검증 환경은 Mac ARM64, Python 3.14.7, Node 24.18.0, pnpm 11.13.0이다.

- `TRADING_TEST_DB=1 uv run pytest`: 984개 통과. 통합 DB는 기존 로컬
  `127.0.0.1:55432/trading`만 사용했다. 새 API 36개·합성 생성기 12개 검사를 포함한다.
- `uv run ruff check .`, `uv run ruff format --check .`: 통과, Python 112개 파일 포맷 일치.
- `mise run web-check`: OpenAPI 일치, 생성 클라이언트 16개 파일 일치,
  Svelte·TypeScript 오류·경고 0개, Vitest 7개 통과.
- 프론트 프로덕션 빌드와 `pnpm --dir web format:check`: 통과.
- Playwright Chromium 7개 통과: 빈 저장소, 명시적 계좌 전환, 소수·통화·미확인 값,
  기록 참조 이동, 키보드 검색, 오류 복구, 늦게 도착한 응답, 모바일 가로 넘침을 검사했다.
  실제 빌드·FastAPI를 임시 합성·빈 저장소와 함께 8871·8872에서 실행하고 정리했다.
- 별도 합성 앱의 IAB 브라우저에서도 계좌 선택과 판단→가설→근거 이동을 확인했다.
  콘솔 오류·경고가 없었고 1536×1024 데스크톱·390×844 모바일 렌더를 검토했다.

Python 테스트에는 외부 Starlette 테스트 클라이언트의 httpx·AnyIO 사용에 관한
deprecation 경고 2개가 있다. 테스트 실패는 없으며 해당 의존성의 후속 호환성 정리는 남아 있다.
테스트는 합성 자료와 임시 저장소를 사용했다. 실제 토스 API·키체인·주문을 호출하거나
개인 자료를 테스트 fixture로 사용하지 않았다.

‘저장 자료 다시 읽기’는 로컬 파일 재조회다. 이 단계에는 새 관측 수집, 지속 실행 작업·
worker, 별도 모델 실행, 주문 전송이 없다. 다음 기능 18은 PostgreSQL에 작업·실행 상태를
보존하는 Python worker 기반이다. 이후 시장 관측과 AI 재판단을 연결하되 **자료 관측 주기,
AI 재판단 시점, 포지션 보유 기간을 각각 상황에 맞게 결정**한다. 장중·일일 같은 고정
운용 방식이나 특정 종목군·분석 방법으로 투자 판단을 제한하지 않는다.

rebase했다. 원래 기능 패치와 파일 내용은 rebase 전후 동일했다.

PR 검토에서 큰 결과를 저장한 뒤 MCP 출력 제한 때문에 실패로 반환하는 문제를 재현했다.
후속 14번의 독립적인 MCP 수정과 회귀 테스트 4개를 13번에 먼저 반영했다.
저장이 완료되면 큰 본문 대신 저장 ID·완료 상태·본문 생략 이유를 반환하고 재시도를

포함하지 않았다. 후속 14번 rebase 시 이 수정이 중복되는 점을 확인한다.

Python 3.14.7의 별도 작업 공간에서 PostgreSQL 통합 테스트를 포함한 전체 867개와
Ruff 검사·포맷 검사가 통과했다. 실제 stdio MCP 연결에서 도구 12개 탐색, 빈 문맥 조회,
큰 합성 연구 기록의 저장 성공 응답과 파일 대조를 확인했다. 프로젝트 설정기의 최초 설정과
재실행 시 파일 보존도 확인했다. 검증은 임시 작업 공간과 합성 자료를 사용했으며 실제
토스 API·사용자 계좌·프로젝트의 기존 MCP 설정은 변경하지 않았다.

## 최초 구현 당시 상태

기본 데이터는 **합성 자료**다. 추천·백테스트·기간/비용 검증·조회·원응답 보존·로컬 운영을
구현했다. 실제 시장에서의 초과수익, 실전 추천 준비 완료, 실제 계좌 연동은 입증하지 않았다.
자동 주문 기능은 없다. UI에 표시되는 합성 종목과 125만 원 예시는 사용자의 실제 계좌가 아니다.

추천 연구의 첫 규칙은 유동성 필터를 통과한 국내·미국 주식의 시장별 12-1개월 모멘텀,
월별 재검토, 진입/유지 순위 완충, 종목·업종·국가 비중 상한이다. 현재 설정은 검증 대상이며
최적값이 아니다. 재무·공시 AI 신호는 아직 추가하지 않았다.

## 브랜치와 작업 방식

2026-09-10 아홉 번째 PR 준비 시점의 `main`은 `982d3d7`이며, 첫 번째부터 여덟 번째
기능의 PR 병합을 포함한다. `feat/09-local-operations`는 이 `main` 위로 rebase했다.
병합된 앞선 로컬 브랜치는 정리했으며, 아홉 번째 기능의 PR 병합은 아직 남아 있다.

아래 표는 **최초 일괄 구현 완료 시점의 이력**이다. 당시에는 각 기능을 앞선 기능의
완료 커밋에서 새 브랜치로 분기했고, `main`에는 문서 초기 커밋만 있었다.
표의 커밋은 이후 rebase로 달라질 수 있으며 현재 브랜치 목록을 뜻하지 않는다.

| 브랜치 | 완료 커밋 / 내용 |
| --- | --- |
| main | b83e26e · 문서 초기 상태 |
| feat/01-project-foundation | 8cb8890 · Python·mise·로컬 PostgreSQL |

최초 일괄 구현 때는 원격 push와 PR 생성·병합을 수행하지 않았다. 이후 사용자가
앞선 기능의 PR 생성·병합·pull 완료를 순서대로 확인했다. 원격 push에는 정확한
원격·브랜치에 대한 사용자 승인이 필요하며, push 승인이 PR 병합 승인을 뜻하지 않는다.
기능 추가는 기존 변경을 확인하고 새 브랜치에서 순서대로 진행한다.

## 최초 구현 완료 시점의 검증 증거

아래 플랫폼 비교와 산출물은 최초 구현 당시 기록이다. 이후 PR 준비 과정에서
해당 검사를 모두 다시 실행했다는 뜻은 아니며, 코드 변경 후 필요한 검사는 다시 수행한다.

- 최종 전체 테스트 590개와 Ruff 검사·포맷 검사가 통과했다. PostgreSQL 통합 검사를 포함한다.
- 추천, 전체 백테스트, 아홉 조건 평가의 전체 JSON과 ID가 Mac ARM64와 Linux ARM64에서 일치했다.
- Linux AMD64 이미지를 로컬 에뮬레이션으로 빌드·실행했고 아홉 조건 평가 전체 JSON도 일치했다.
  이는 prod-01 실측이나 부하 시험은 아니다.
- 브라우저에서 추천 저장, 자료와 저장 기록 조회, 손실을 포함한 결과 표와 차트를 확인했다.
- 1,000종목 합성 자료에서 기존 방식과 인덱스 방식의 조회 결과를 비교했다.
  [성능 측정](PERFORMANCE.md)의 범위와 한계가 적용된다.
- 백업을 새 임시 DB에 복원해 8개 테이블의 모든 행·스키마·인덱스·revision을 대조했고
  원본 보존과 임시 DB 정리를 확인했다. 성공 기록은
  `var/backups/trading-20260909T160440Z-67ae1b56ebe746c9b85a3370903b59c6.json`이다.
  같은 이름의 `.dump`가 보존되어 있다. 파일명 시각은 UTC다.
- 로컬 실행 산출물은 Git에서 제외된 `var/`에 보존한다. 기본 데모 원본은 `var/demo/`,
  추천·시뮬레이션·평가는 `recommendation.json`, `backtest.json`, `evaluation.json`이다.
  플랫폼 대조는 `platform-parity.json`, 컨테이너 상태는 `container-runtime.json`에 기록했다.
  큰 자료의 동등성과 속도 재검사는 `market-view-benchmark.json`에 보존했다.
- 실행마다 모든 상세 결과를 덮어쓰지 않고 ID별 DB 기록을 보존한다. 개발 중 과거 기록은
  이전 코드의 결과이며 최신 구현과 같은 기록 ID일 필요가 없다. 잘못되거나 불완전한 연결은
  현재 조회 검증이 거부한다.

다음 항목은 투자 연구 자체의 남은 작업이다.

1. [Codex 도구](CODEX_TOOLS.md)의 현재 문맥부터 읽고 필요할 때 계좌를 갱신한다.
   삼성에 남아 있는 자산·이번 월 납입 완료·실제 투자 재원은 사용자 확인 사항으로 남아 있다.
   계좌 관측만으로 현금이나 매수·매도 우위를 추정하지 않는다.
2. 과거 상장폐지 포함 종목군, 자료 공개 시점, 기업행사와 총수익 조정, 거래 달력·환율을
   검증한 실제 자료를 가져온다. 원응답을 보존했다는 사실만으로 과거 자료 계약을 충족하지 않는다.
3. 비용·거래 가능성·현금 결제 제약을 계좌에 맞게 확정하고, 규칙 분석과 AI 판단을
   실제 자료·후속 관측으로 평가한다. 특정 스타일로 고정하거나 성과가 좋은 기간만 고르지 않는다.
4. 실제 투자 비중과 중단 기준은 결과를 바탕으로 다시 정한다. 9월 10일 월 납입 완료도
   아직 확인하지 않았으므로 사용자의 현금에 자동 반영하지 않는다.

세션이 바뀌면 이 문서와 `TECH_STACK.md`, `IMPLEMENTATION.md`, `git status`부터 확인한다. 작업량이나
합성 검사 통과를 실제 수익성 증거로 바꾸어 해석하지 않는다.
