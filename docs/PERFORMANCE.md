# 시장 조회 성능 측정

`scripts/benchmark_market_views.py`는 변경 전 eager 조회와 `MarketView`의 인덱스 조회를 동일한 합성 자료에서 비교한다. 실제 시장 데이터나 수익성을 검증하는 도구가 아니다.

프로젝트 루트에서 실행한다.

```sh
.venv/bin/python scripts/benchmark_market_views.py > var/market-view-benchmark.json
```

기본값은 종목 1,000개, 평일 세션 400개, 일별 평가 100회, 평가당 보유 종목 8개, 반복 3회다. 작은 실행으로 기능을 확인할 때는 `--stocks 64 --sessions 400 --views 20 --repeats 1`을 사용할 수 있다. 결과 JSON은 표준 출력으로만 내보내며 DB·네트워크·계좌·주문에 접근하지 않는다.

자료에는 고정 seed로 섞은 행 순서, 늦게 공개되는 일봉·환율, 아직 공개되지 않은 종목 정보, 상장폐지·거래량 0·노후화에 따른 제외 사례가 포함된다. 기준 클래스는 `184e1c9`의 `MarketView.__init__`, `latest`, `fx`, `require_current_units`를 보존한다. 가격 환산·평가액·순위 계산은 같은 공개 인터페이스를 사용한다.

측정 전에 다섯 시점까지의 전체 종목 관측 이력·최근 가격·환율·후보 순위·제외 이유를 대조하고, 측정에 쓰는 모든 날짜에서 8개 보유 종목의 평가액을 비교한다. 시점 수와 비교 건수는 JSON에 기록한다. 비교가 실패하면 성능 결과를 반환하지 않는다. 이는 표본 시점과 해당 평가 작업에 대한 동등성 검사이며 모든 가능한 입력을 증명하지 않는다.

초기 비용은 새 `Bundle`에서 인덱스가 없는 상태의 첫 조회와 평가 1회를 측정한다. 반복 측정은 인덱스를 재사용하면서 날짜마다 새로운 조회 객체를 만들고 평가한다. 실행 순서를 번갈아 적용하고 반복 시간·중앙값·최솟값을 모두 기록한다. 합성 자료 생성, 자료 내용 해시, 사전 동등성 검사는 측정 구간에서 제외한다.

메모리는 `tracemalloc`으로 별도 측정한다. 초기 인덱스 구축의 추가 Python 할당과 인덱스를 재사용하는 작업의 추가 할당을 구분한다. 프로세스 전체 RSS, 이미 존재하는 원본 자료·인덱스, 모든 네이티브 메모리를 나타내는 값이 아니다. 메모리 추적 중 시간에는 추적 오버헤드가 있으므로 추적 없는 반복 시간과 직접 비교하지 않는다.

결과에는 Python·운영체제·CPU 수, 자료 크기, 소스 해시, 동등성 범위와 측정 한계를 포함한다. 하드웨어·동시 부하·작업 구성에 따라 결과가 달라진다. 시간 임계치를 단위 테스트로 고정하지 않으며, 이 결과를 전체 백테스트 속도나 투자 우위로 일반화하지 않는다.

## 2026-09-10 로컬 측정

Mac ARM64, Python 3.14.7에서 기본 설정을 실행했다. 제외 사례 때문에 실제 가격 행은
392,530개다. 5개 전체시장 시점의 이력·가격·환율·순위·제외 이유와 100일 평가액이 일치했다.

| 인덱스를 재사용하는 100일 × 8종목 평가 | 3회 중앙값 |
| --- | ---: |
| 이전 전체 자료 조회 | 10.239초 |
| 종목별 인덱스 조회 | 0.001112초 |

초기 인덱스 구축의 추가 Python 할당 최고치는 약 12.94MB였다. 원본 자료 자체와
내용 해시 생성 비용은 포함하지 않는다. 전체 전략의 순위 계산·자료 로드·백테스트 실행이
이 비율로 빨라졌다는 뜻은 아니다. 별도 데모 전체 백테스트에서는 개선 전후 세 계좌의
일별 곡선·체결·원장·손익과 판단 건수, 남은 예약 상태가 정확히 일치함을 확인했다.
최종 재검사의 원본 JSON은 `var/market-view-benchmark.json`에 보존했다.
