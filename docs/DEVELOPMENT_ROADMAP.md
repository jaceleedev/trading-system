# 승인된 후속 개발 범위

2026-09-14에는 기능 27~29의 순차 개발을 추가 승인했다. 기능별 브랜치와 별도의
새 Codex 작업에서 직전 완료 커밋을 이어 구현·검증·로컬 커밋한다. 승인된 상세 범위와
완료 게이트는 [DEVELOPMENT_SEQUENCE.md](DEVELOPMENT_SEQUENCE.md)를 따른다.
27번은 운영 상태·대기 이유·자료 신선도·재검토 요약, 28번은 명시적인 웹 관측 수집,
29번은 조사부터 기간 결과까지의 선택 유지와 단계 이동이다. 출처 저장 강화·새 가격/공시
재판단·실제 자료 모의운용은 이 세 기능 이후 별도 검토한다.

27번은 `feat/27-workbench-operations`에서 구현·검증을 완료했다. Python 2,189개,
Vitest 38개, 웹 E2E 86개와 필수 정적 검사·빌드가 통과했다. worker 관측용 migration
2개를 기존 로컬 DB에 적용했으며 현재 schema는 `b727f04e62d1`이다.
28번은 27번 완료 SHA `b04ca337544df94b6a71259dd52bc7a023ea8af9`에서 이어
`feat/28-web-observation-capture`에 구현·검증했다. Python 2,227개, Vitest 45개,
웹 E2E 103개 및 필수 검사·빌드가 통과했고 새 migration은 없다. 실제 API·DB·worker와
빌드 앱의 브라우저 검증은 합성 외부 transport로 격리했다. 29번은 승인된 다음 작업이며
아직 구현하지 않았다. 실제 결과·제약·완료 커밋·증거는 [HANDOFF.md](HANDOFF.md)
상단과 `/tmp/trading-feature28-completion.txt`를 따른다. 아래는 과거 승인 기록이다.

2026-09-10 사용자는 기능 18~22의 후속 개발과 실제 주문 연결 코드까지의 범위 확장을
승인했다. 기존 토스 보유분과 앞으로 투입하는 자금을 함께 운용 대상으로 설계한다.
투입 금액과 보유 상태는 사용자 설명으로 계좌에 기입하지 않고 실제 관측과 명시적
운용 설정으로 확인한다. 다른 증권사의 자산이나 예정된 매각 대금은 자동 합산하지 않는다.

검증 환경은 현재 Mac이다. 새로운 유료 모델·데이터 계약이나 원격 운영은 추가하지 않는다.
AI는 기존 Codex를 사용하고, 프로젝트는 모델의 판단에 필요한 자료·계산·기록을 제공한다.
관측 주기, AI 재판단 시점, 포지션 보유 기간은 각각 상황에 맞게 바꿀 수 있어야 한다.
특정 시가총액·가격 방향·뉴스·차트·보유 기간을 하나의 고정 전략으로 강제하지 않는다.

## 단계와 완료 조건

단계별로 직전 완료 브랜치에서 다음 브랜치를 만들고, 검증 결과와 제한을 인수인계에
기록한 뒤 로컬 커밋한다. 브랜치 끝점을 보존한다. 원격 push·PR 생성·병합은 이번
개발 승인이 포함하지 않는다. 범위가 커지면 검토 가능한 단위로 나눌 수 있다.

## 실제 운용과의 경계

2026-09-11 기준 18~26번의 구현·검증을 각 로컬 브랜치에 완료했다. 완료한 동작과
계약상 미확인 범위, 단계별 검사 결과는 [인수인계](HANDOFF.md)에 기록했다. 26번은
모의 기간 평가와 실제 브로커 관측 문맥을 분리하며 관측에 없는 실계좌 손익·현금 흐름·
환율 효과나 개별 체결을 생성하지 않는다. 원격 PR 처리나 실제 운용 시작을 뜻하지 않는다.

주문 연결 기능 개발 승인은 실제 주문 전송 승인이 아니다. 개발·검증 동안 실제
증권사 주문 전송을 비활성 상태로 유지한다. 호출 계약을 구현하거나 합성 체결을
저장한 결과를 실제 주문·체결로 기록하지 않는다. 실행할 수 없는 부분이나 검증하지
못한 증권사 동작은 완료한 부분과 분리해 보고한다.

현재 상태와 단계별 실제 결과는 [인수인계](HANDOFF.md)를 따른다. 시장·증권사와
모델의 세부 기능은 구현 시 공식 계약 및 실제 실행 환경에서 확인한다.
