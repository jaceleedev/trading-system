# 기간별 결과와 판단 연결

작업실의 **기간별 결과 비교**에서 모의 원장과 AI 운용 흐름을 각각 최대 4개까지
명시적으로 선택한다. 기간은 시스템에 기록된 시각을 기준으로 하며 시작은 제외하고
종료는 포함한다. 시작 시점까지 기록된 원장 상태와 종료 시점까지의 상태를 비교한다. 이 기간 입력은
투자 전략의 보유 기간이나 AI 재검토 주기를 고정하지 않는다.

모의 원장은 원장별·통화별 시작과 종료 평가액, 평가 변화, 단순 수익 비율, 모의 비용을
보여 준다. 서로 다른 원장이나 통화의 금액을 합산하지 않는다. 기존 보유의 과거 취득원가를
포함한 실현 손익은 기간 시작 이후 평가 변화와 별도로 표시한다. 가격·원가·현금이
확인되지 않은 값은 0으로 채우지 않는다.

운용 흐름은 연결된 브로커 대조의 누적 수량·금액·비용 변화를 보여 준다. 이는 개별
실제 체결이나 실제 손익을 확정하는 자료가 아니다. 실제 현금 흐름, 입출금, 환율 효과,
주문 출처 등 원문에 없는 정보는 미확인으로 남긴다. 운용 흐름에 연결된 대조가 요청
기간 밖에 있더라도 문맥 자료로 표시할 수 있다. 이때 이전·이후 관측 시각과 **기간 불일치**를
함께 표시하며 대조 값을 요청 기간의 체결로 배분하지 않는다. 실제 주문 전송은 비활성이다.

보고서의 판단 방식 연결에서 자금 계획과 AI 조사 입력·출력·실행 기록을 확인한다.
요청한 모델 설정과 실행 과정에서 확보한 메타데이터를 구분하며, 모델의 실제 정체가
확인되지 않은 경우도 그대로 표시한다. 여러 판단 방식이 같은 원장에 영향을 주거나
자료·기간·초기 자산이 다를 수 있으므로 화면이 자동으로 우승 모델이나 인과적 성과를
정하지 않는다.

계산한 보고서는 선택한 자료와 기간을 포함한 변경 불가능한 기록으로 저장한다.
저장된 보고서를 다시 열어 같은 기준과 미확인 항목을 확인할 수 있다. 자료가 추가되면
새 보고서를 계산한다. 종료 시각을 비우면 최초 처리 시 서버가 확정한다. 응답을 확인하지
못한 경우 화면의 **같은 계산 요청 결과 확인**은 원래 선택 자료·기간·요청 식별자를
재사용한다. 새 입력을 선택해도 미확정 요청이 다른 계산으로 바뀌지 않는다.

새 계산에는 로컬 작업 저장소(`--jobs`)가 필요하다. 이미 저장한 결과 보고서의 목록·상세는
DB 없이 읽을 수 있다. 보고서 조회와 생성은 각각 `GET /api/v1/outcomes`,
`GET /api/v1/outcomes/{id}`, `POST /api/v1/outcomes`로 제공한다. 보고서의 모의 금액과
수익 비율은 소수 문자열을 그대로 표시하며, `0.1`은 수익 비율 `10%`를 뜻한다.
계산 정밀도 차이의 잔차도 현금·비용·취득원가 손익별로 확인할 수 있다.

## 기록과 재계산

한 번의 PostgreSQL 읽기 전용 `REPEATABLE READ` 트랜잭션에서 자료를 고정한다.
모의 원장은 각 경계 이전의 마지막 요청 영수증으로 상태를 복원한다. 현재의 주문 선택
상태를 과거 원장에 끼워 넣지 않는다. 운용 흐름·주문은 전체 현재 상태가 종료 시각 이전인
경우만 포함하며, 종료 이후 변경된 흐름의 과거 상태를 추정해서 보여 주지 않는다.
기록 시각은 트랜잭션이 다른 세션에 보이기 시작한 시각을 인증하지 않는다.

기간 중 요청 영수증은 총500개, 공개 이벤트와 흐름·주문 이력은 총5,000개, DB 발췌는
8MiB로 제한한다. 초과하면 기간이나 선택 범위를 줄이도록 거부하며 일부 자료로 성과를
완성하지 않는다. 원장의256자리 소수 회계를 영수증마다 재계산해 대조하고 보고서는
1,536자리 문맥을 사용한다. 시작 시점에 없던 가격을 종료 시점 가격으로 채우지 않는다.

`var/outcomes`에는 입력 발췌와 보고서를 각각 SHA-256 ID로 저장한다. 원본 계좌·계획·
시세·조사·브로커 자료를 함께 확인한 후 재계산 결과까지 비교한다. 로컬 해시와 자료 연결은
시장 사실, 실제 실행 또는 모델의 정체를 인증하지 않는다. 뒤늦게 저장된 모델 실행 기록을
이미 저장한 보고서의 판단 방식에 자동 추가하지 않는다. 같은 출력을 가리키는 실행 기록이
여럿이면 미확정으로 표시하고 임의의 실행 모델을 고르지 않는다.

종료 시각을 비운 동일 요청의 동시 처리는 DB에 처음 등록된 보고서로 수렴한다. 등록 전
중단이나 경쟁으로 생긴 검증 가능한 입력·보고서 파일은 보존한다. 파일 목록에는 이런
자료도 포함될 수 있으며, 파일 개수는 완료된 사용자 요청 수를 뜻하지 않는다.

브로커의 **기간 일치**는 계좌 완료 시각뿐 아니라 보유·통화별 매수 가능 금액·이전/이후
주문 스캔의 관측 경계도 모두 일치할 때만 표시한다. 여러 요청으로 수집하는 실제 자료는
시각이 다를 수 있다. 이전 스캔이 없으면 정확한 동일 기간의 변화로 표시하지 않는다.
모의 원장은 초기 현금 이후 외부 입출금이나 환전 처리를 지원하지 않는다. 따라서 통화별
평가 변화를 계산할 수 있지만 실제 입출금·환율 효과를 분해한 실계좌 수익률은 제공하지 않는다.

## CLI와 백업

계산 입력 JSON은 `book_ids`, `workflow_ids`, UTC `start_at`, 선택적 `end_at`, `mode`,
`request_key`를 사용한다. 모의 검사에서는 명시적인 `--synthetic` 작업실을 사용한다.

```sh
uv run trading outcomes create --workspace /path/to/workspace --synthetic --input /path/to/request.json
uv run trading outcomes list --workspace /path/to/workspace
uv run trading outcomes show --workspace /path/to/workspace --id REPORT_SHA256
```

[개인 자료 백업](ARTIFACT_BACKUP.md) v5는 입력·보고서와 참조 원본을 포함하며 v1~v4
manifest identity도 유지한다. 복원된 발췌는 보고서 재계산용이다. 작업·배정·주문·원장을
다시 운용하려면 별도의 DB 백업이 필요하다.
