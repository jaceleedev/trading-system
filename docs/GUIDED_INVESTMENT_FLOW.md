# 투자 단계 이어가기 (기능 29)

조사 → 계획·대안 → 모의 원장 → 기간 결과를 선택한 출처와 함께 이어 읽는다.
기존 조사·자금 계획·모의 매매·기간 결과 패널의 수동 선택과 실행도 계속 사용할 수 있다.
단계 이동은 저장 자료 조회와 입력 채우기다. 조사 접수, 예산 적용, 자금 배정, 모의
원장 생성·대안 고정·진행, 기간 결과 계산은 사용자가 별도 실행 버튼을 눌러야 한다.
계획·대안·예산이 없으면 해당 입력으로 안내하며 임의의 금액이나 계획을 만들지 않는다.

## 선택과 출처

상단 계좌 관측은 사용자가 명시적으로 선택한다. 조사에 고정한 과거 관측은 상단의
새 관측으로 교체하지 않는다. 같은 계좌의 다른 관측을 선택하면 현재 표시 관측과
과거 출처 관측을 구분한다. 다른 계좌로 바꾸면 종속 선택을 재검증하고 부적합한
연결을 해제하거나 보류한다. 과거 자료 탐색이 상단 계좌를 조용히 바꾸지 않는다.

`GET /api/v1/guided-flow`는 선택한 계좌 관측·조사 ID·revision·출력 ID·계획·대안·
원장·보고서를 읽기 전용으로 검증한다. 브라우저가 보관한 ID는 복원 힌트다.
조사 revision의 실제 입력·결과·실행 기록 연결, 계획의 원래 출력과 관측, 원장에
고정한 계획과 대안, 보고서 기간에 고정된 원장·대안 출처를 다시 대조한다.
각 ID가 존재한다는 사실만으로 전체 연결을 인정하지 않는다.

이미 선택 대안이 고정된 원장과 앞으로 그 대안을 입력할 수 있는 원장은 구분한다.
결과 보고서는 해당 기간에 고정된 출처로 판단하며, 보고서 생성 뒤 원장에 추가된
대안을 과거 보고서의 출처로 붙이지 않는다. 통화·모드를 섞어 금액을 합산하지 않는다.
자료 누락·불일치·저장소 장애는 현재 성공 결과로 표시하지 않는다.

## 새로고침과 복구

선택은 주소의 조회 인수로 이어진다. 새로고침과 브라우저 뒤로 가기는 저장 선택을
서버에서 다시 검증하고 조회한다. 진행 중 요청보다 나중에 계좌나 선택을 바꾸면
늦은 응답이 현재 선택에 적용되지 않는다. 자동 조회는 기존 기능 27의 보이는 화면과
시간 제한을 따르며 새 실행을 접수하지 않는다.

실행 요청은 접수 전에 workspace별 브라우저 영수증에 원래 키와 입력을 보관한다.
응답 유실 후 새로고침해도 새 키를 만들거나 자동으로 재실행하지 않는다. 원래 입력의
명시적 재확인만 제공하며 서버의 기존 idempotency·revision·출처 검증을 재사용한다.
브라우저 저장에 실패하면 새 실행을 막는다. 브라우저 저장소를 직접 삭제하거나 다른
브라우저로 옮기는 것은 요청 영수증 복구를 보장하지 않는다.

기존 파일 기반 계좌·시장·연구·계획·저장 결과 조회는 DB 없이 유지한다. 실행 중
조사 상태와 현재 모의 원장은 PostgreSQL 기록이 필요하다. API 설정과 자료의 검증
가능 범위를 화면에서 구분한다. 새 migration, 주문 전송, 추가 모델·데이터 서비스는 없다.

검증 결과와 실제 로컬 런타임의 합성 경계·증거는 [HANDOFF.md](HANDOFF.md)를 따른다.
