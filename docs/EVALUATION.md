# 고정한 규칙의 기간·비용 검증

```bash
uv run trading db-upgrade
uv run trading evaluate --dataset synthetic-demo-v1 \
  --plan configs/evaluation.demo.json --save > var/evaluation.json
```

전략은 한 번 정한 설정을 그대로 사용한다. 겹치지 않는 세 기간에 기본 비용·2배·3배를
각각 적용하고 **모든 조합의 결과**를 남긴다. 가장 잘 나온 설정을 자동 선택하거나
손실 결과를 제외하지 않는다. 비용 가정만 바꾸므로 아홉 번의 독립된 통계 검증은 아니다.

예시 계획의 development, validation, reserved는 각각 초기·중간·마지막 평가 구간이다.
마지막 구간을 나눴다는 사실만으로 사전에 보지 않은 독립 데이터가 되는 것은 아니다.
과거에 어떤 결과를 확인했는지 입증하는 기록이 없으므로 미열람 독립성은 미검증이다.
실제 독립 검증에는 접근을 분리한 자료와 설정 확정 시각, 이후 변경 내역이 필요하다.

## 계산과 기록

- 세 기간은 시간순이며 중복 날짜를 허용하지 않는다. 각 기간은 같은 초기 자본으로
  시작하고 같은 규칙으로 월 납입한다. 기간 사이 보유량·현금을 연결하지 않는다.
- 고정 비용 배수 1·2·3이 매수·매도 비용 가정에 각각 적용된다. 신호·비중·교체 규칙은 같다.
- 요약의 각 사례는 전체 백테스트 ID와 결과 해시를 가리킨다. 아홉 사례의 계산이 끝나야
  요약과 원본을 같은 DB 트랜잭션에 보존한다. 중간 실패를 완성된 검증으로 저장하지 않는다.
- 자료 원문·내용, 전략 설정, 계획, 코드가 식별에 포함된다. 과거 기록을 새 결과로
  덮어쓰지 않는다. 요약 조회 시 원본 백테스트의 존재와 체크섬도 검사한다.
- 화면 ‘반복 검증’에서 전체 표와 JSON을 확인한다. 같은 결과를 재계산해도 새 증거가
  여러 개 생긴 것으로 세지 않는다.

## 결과를 해석하는 순서

납입을 제외한 수익·낙폭·체결 수를 보고, 비용을 올렸을 때도 결과가 유지되는지 확인한다.
국가별 비교 계좌와 전략의 노출이 다르므로 TWR 차이를 곧바로 위험 조정 초과수익으로
부르지 않는다. 각 기간 자금이 재시작하므로 표의 손익을 단순 합산해 연속 운용 성과라고
해석하지 않는다.

현재 자료는 합성 fixture다. 여기서 통과한 것은 구현의 재현성과 회계·표시 흐름이며,
투자 우위는 입증되지 않았다. 실제 운용 판단에는 공급자 시점/종목군/기업행사 감사,
매매 및 환전 비용 확인, 실제 미래에 기록한 추천과 모의운용 결과가 더 필요하다.
manifest의 ‘historical’이나 ‘point_in_time’ 선언만으로 감사 완료 상태가 되지는 않는다.
