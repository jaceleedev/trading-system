# 개인 연구 화면 사용법

```bash
docker compose up -d --wait postgres
uv run trading db-upgrade
mise run ui
```

브라우저에서 <http://127.0.0.1:8501>을 연다. 이 주소는 해당 Mac에서만 접근한다.
자료가 없으면 README의 데모 생성·가져오기를 먼저 실행한다. 합성 데이터는 화면 위에
항상 표시되며, 실제 보유 주식이나 현재 시세를 뜻하지 않는다.

## 추천 만들기

1. 사용할 자료를 고르고 확인한 원화 현금, 판단 기준 시각, 계좌 확인 시각을 입력한다.
2. 보유 종목은 표에 행을 추가해 선택하고 정수 수량을 입력한다. 빈 표는 주식 미보유다.
   중복 종목과 미완성 행은 거부한다. 기존 한전기술 보유량이나 예정 납입을 자동 입력하지 않는다.
3. ‘추천 계산하고 기록하기’를 누르면 당시 공개된 데이터로 계산하고 기록한다.
4. 매매 검토안에서 수량·기준 가격·이유와 가정한 비용, 후보·제외 이유를 확인한다.
   차트의 빈 마커는 그 판단 시각의 **미체결 제안**이다. 미래 가격이나 자동 체결 표시가 아니다.

입금 예정액을 현금으로 입력하지 않는다. 계좌 시점이 기업행사 전이면 잔액 갱신을 요구한다.
입력 오류로 새 계산이 실패하면 이전 계산을 새 결과처럼 표시하지 않는다. 이전 결과는
‘저장한 기록’에서 다시 열 수 있다. 계산은 실제 현금·보유량을 변경하지 않는다.

## 과거 성과

시작·종료일, 초기 자본, 월 납입·납입일, 국가별 비교 기준을 선택한다. 비용 배수는
매수·매도 비용 가정을 함께 높이는 민감도 확인용이다. 좋은 결과만 남기는 기능은 없다.
모든 계산 결과는 자료·설정·코드 해시와 함께 저장한다.

평가액에 포함된 납입금, 납입을 뺀 손익, TWR과 낙폭을 각각 확인한다. 차트는
시간가중수익률과 누적 평가액 사이를 전환할 수 있다. 모의 체결·원장·종목별 매매 표시를
함께 제공한다. [회계 및 체결 가정](BACKTEST.md)의 제한을 따른다.

## 데이터와 기록

‘데이터 살펴보기’에서 자료 범위·종목·출처·원문 및 내용 해시를 확인한다. 필드 정의는
[입력 계약](DATA_CONTRACT.md)에 있다. ‘저장한 기록’은 자료별 최신 50개 결과를 조회한다.
결과 JSON은 계산 근거와 전체 원장을 포함해 내려받을 수 있다. 저장 결과의 체크섬이
다르면 정상 결과로 표시하지 않는다.

‘반복 검증’은 [고정 계획](EVALUATION.md)의 기간·비용 조합을 모두 실행하고 조회한다.
사례별 원본 백테스트도 함께 저장되며 마지막 구간의 미열람 독립성은 별도로 표시한다.

## 화면 검증

Streamlit AppTest로 추천 생성·저장 기록 조회, 입력 실패 시 이전 결과 제거, 납입/손익
분리 표시, 자료 없음과 DB 오류 흐름을 검사한다. 공식 [AppTest 문서](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest)를 따른다.
실제 로컬 브라우저에서도 추천표·차트·저장 이력을 확인한다.
