# AI 운용 워크플로

완료된 AI 조사의 수량·가격·비용 제안을 기존 사용자 예산과 연결하고, 계산·배정·주문 의도·후속 대조를 하나의 흐름으로 관리한다. 실제 주문 전송은 계속 비활성이다. 조사 접수, 모델 실행, 자금 배정, 브로커 응답과 체결 관측은 각각 다른 기록이다.

## 시작할 때

1. 상단에서 사용할 계좌 관측을 명시적으로 선택한다.
2. 완료된 조사를 읽고 V2 결과의 대안을 선택한다. 대안의 매수·추가·유지·축소·매도 항목은 한 묶음으로 확인한다. 교체 판단이면 매도와 매수를 같은 대안 안에서 검토한다.
3. 서버에 저장된 해당 계좌의 계획 예산과 유보 금액을 확인한다. AI 제안은 새로운 예산 승인이 아니다. 예산 변경이 필요하면 자금 계획에서 사용자가 직접 적용한다.
4. 수량·가정 가격·수수료·세금이 미확인인 부분을 확인한다. 누락값을 화면이 0이나 임의 가격으로 채우지 않는다. 완결된 대안을 선택해 워크플로를 저장한다.

기존 V1 조사 결과는 계속 읽을 수 있다. V2 제안이 없는 결과를 수량이 확정된 운용 제안으로 취급하지 않는다. 특정 시장 방향, 시가총액, 뉴스·차트 유형, 고정 조사 주기나 보유 기간을 강제하지 않는다.

## 진행과 중단

워크플로 화면에서 저장한 입력, 단계별 결과 참조, 현재 상태와 처리 오류를 확인한다. 진행은 기존 자금 계산·배정·주문 관리 기능을 연결한다. 각 단계가 성공했다는 것은 해당 로컬 처리가 기록되었다는 뜻이며 실제 거래의 성공이나 수익을 뜻하지 않는다.

요청 결과를 받지 못하면 같은 요청 식별자로 확인한다. 다른 계좌나 대안을 선택해도 진행 중인 요청의 원래 입력은 바뀌지 않는다. 일시정지는 이후 진행을 제어하며 이미 저장한 결과·배정·주문을 자동으로 취소하거나 해제하지 않는다. 중단 복구는 기록된 단계와 결과를 확인하는 절차이고, 불확실한 실제 주문의 재전송 허가가 아니다.

## 후속 자료 대조

이후 계좌 관측과 이전·이후 브로커 스캔을 명시적으로 선택해 대조한다. 관측의 기록 시각과 조회 범위를 보존하며 브로커 누적 수량·금액의 변화, 비용 정정, 연결이 확인되지 않은 보유 변화를 구분한다.

브로커 GET 자료에 없는 개별 체결 ID나 주문 출처는 추정하지 않는다. 출처 미연결을 수동 매매라고 단정하거나 누적 변화를 이번 AI 판단의 실제 손익으로 표시하지 않는다. 정정 후 브로커 주문 ID가 바뀌면 이전 ID의 관측을 새 ID의 현재 상태로 사용하지 않는다.

## 자료의 의미

- 매수 가능 금액은 현금 잔고가 아니다. 통화별 예산·금액은 환산 근거 없이 합치지 않는다.
- 계산과 배정은 선택한 관측·기존 예약·사용자 예산에 의존한다. 최신 상태가 바뀌면 충돌이나 재확인이 필요할 수 있다.
- 합성 작업실은 합성 자료임을 표시한다. 합성 실행 결과는 실제 브로커나 모델 실행의 증거가 아니다.
- 기록 ID와 해시는 로컬 무결성과 연결을 확인한다. 외부 사실의 진실성·자료의 완전성·실제 체결을 보증하지 않는다.

## 구현과 복구 범위

새 조사 입력은 schema_version2로 기존 예산 관측을 고정한다. 새 출력도 V2의
capital_proposal을 사용하며, 기존 V1 입력·출력·실행 기록은 원래 스키마로 검증한다.
출력 파일의 해시와 실행 프로토콜, DB가 채택한 조사 revision을 별도로 확인한다.
워크플로 생성 요청은 조사 ID·완료 revision·대안 key만 받으며 모델 출력이나 실행 인증
JSON, 새 운용 한도를 직접 받지 않는다.

진행 요청 한 번은 자금 상태 반영→계획 저장→배정→비활성 주문 의도 중 한 단계만
처리한다. 그 후에는 명시적으로 선택한 주문 스캔과 이후 계좌 관측을 연결한다.
최종 completed는 이 로컬 흐름의 대조 보고서가 저장됐다는 뜻이다. 실제 주문의 체결·
취소 완료나 자금 배정 해제를 뜻하지 않는다. 미확정 주문의 배정은 계속 유지된다.

PostgreSQL의 operation_workflows/operation_workflow_steps는 입력·원래 요청 key를
처리 전에 저장한다. 임대가 만료되면 확인 대기로 남고, 재개는 원래 입력의 멱등적 로컬
효과를 확인한다. 저장된 원문이 없거나 자금 상태가 충돌하면 자료를 임의로 바꾸지 않는다.
일시정지 중 도착한 처리 결과는 기록해도 다음 단계를 시작하지 않는다.

HTTP는 `/api/v1/workflows` 및 `proposal/{investigation_id}`, `{id}` 조회,
`{id}/advance|pause|recover|resume|observe|reconcile` 제어를 제공한다. `--jobs`가
없는 서버에서는 비활성이다. CLI는 `trading workflows create|list|show|proposal|advance|
pause|recover|resume|observe|reconcile`과 `--workspace`, `--id`, `--input`을 사용한다.
합성 작업실에는 `--synthetic`을 명시한다. 실제 주문 전송 명령은 없다.

파일 백업 v5는 V1·V2 조사 원문을 모두 검증하며 기존 백업의 manifest identity를 보존한다.
살아 있는 단계·배정·주문 기록은 파일 백업 외에 같은 로컬 PostgreSQL 백업이 필요하다.
