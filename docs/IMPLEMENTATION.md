# 구현 및 인수인계

2026-09-10 최초 후속 개발은 `main`의 기능 1~9 병합 완료 커밋 `e10394c`부터 시작했다.
기능별 새 브랜치에 로컬 커밋한 뒤 개별 PR을 순서대로 준비했다. PR16 기술 결정까지
병합한 `main`에서 기능 17 웹·API를 구현했다. 최신 방향·브랜치 상태·검증 결과는
[HANDOFF.md](HANDOFF.md) 상단을 우선한다.

`feat/17-investment-web-api`는 [기술 스택 결정](TECH_STACK.md)에 따라
Svelte 5·SvelteKit·TypeScript 화면과 읽기 전용 FastAPI를 도입한다.
기존 공통 Python 조회 서비스로 계좌 관측·판단·근거를 연결하며, OpenAPI에서
TypeScript 클라이언트를 생성한다. PostgreSQL 작업 기록과 Python worker는 후속 작업이다.
초기 TimescaleDB·pgvector·Redis는 제외하며 기존 Streamlit 실행도 유지한다.
실행·검증 방법은 [웹 작업실](WEB_WORKBENCH.md)을 따른다.

사용자는 2026-09-09 로컬 구현, main 초기 커밋, 기능별 순차 브랜치 작업을 요청했다.
기존 문서 전용 상태에서 추천·연구 시스템 구현으로 범위가 확대됐다.
당시 최초 구현 범위에는 자동 주문, 회사 production 변경, 원격 Git push가 포함되지 않았다.
이후 PR 준비 과정의 push는 사용자가 승인한 기능 브랜치에 한해 진행했다.

## 최초 구현 당시 브랜치 진행 방식

`main`의 문서 초기 커밋을 기준으로 기능을 하나씩 완성·검증·커밋했다.
다음 기능 브랜치는 직전 기능의 완료 커밋에서 분기했으며 각 브랜치는 앞선 기능을 포함했다.
아래 목록은 이 최초 일괄 구현 순서다. 당시 main 자동 병합이나 원격 push는 수행하지 않았다.

1. `feat/01-project-foundation`: mise, Python, 잠금 의존성, 로컬 PostgreSQL, 검사 도구.
2. 데이터 기능: 입력 검증, 데이터 시점·출처, 스키마와 가져오기.
3. 전략 기능: 중기 상대강도, 주문 단위·비용을 고려한 추천, 변경 불가능한 추천 기록.
4. 검증 기능: 과거 시점 재현, 다음 거래일 모의 체결, 납입·손익 분리와 비교 기준.
5. 화면 기능: 추천·데이터 상태·성과·검증 제한을 확인하는 개인 화면.
6. 토스 시장 자료: 공개 시장 GET 허용 목록, 원응답 보존과 수집 계약.
7. 반복 검증: 고정 기간·비용 가정, 연결 검증과 화면.
8. 처리 속도: 종목별 조회 인덱스, 계산 동등성 검사와 합성 벤치마크.
9. 운영: Docker 이미지, 플랫폼 대조, 로컬 백업·복원 및 인수인계.

## 현재 구현의 기술 구성

- Mac mise의 프로젝트 Python은 일반 CPython 3.14.7로 고정한다. 전역 설정은 바꾸지 않는다.
- Python 의존성은 `uv.lock`, 프론트 의존성은 `web/pnpm-lock.yaml`로 고정한다.
  Node 24.18.0·pnpm 11.13.0은 웹 개발·빌드에 사용한다. 빌드된 웹 화면은 FastAPI가
  같은 출처에서 제공하므로 운영에 별도 Node 서버가 필요하지 않다.
- 저장소는 PostgreSQL. 로컬 개발은 별도 Compose 프로젝트/볼륨과 localhost 55432를 사용한다.
- prod-01은 2026-09-01 문서상 16코어/32스레드, RAM 122GiB, NVMe 2TB다.
  실제 부하와 신규 배치는 아직 검증하지 않았다. 회사 DB·계정·배포 설정은 재사용하지 않는다.
- 제공된 계좌 금액과 납입 예정은 사용자 신고값이다. 납입 완료나 최신 시세로 취급하지 않는다.

## 검증 원칙

추천은 실제 보유나 현금을 변경하지 않는다. 데모 자료의 성과는 시장 성과가 아니다.
자료의 경제적 날짜와 실제 이용 가능 시각을 구분한다. 과거 종목군·기업행사·환율을
지원하지 않는 자료로 완전한 투자 성과를 주장하지 않는다. 미지원 조건은 명시적으로 거부한다.

각 기능의 완료 상태와 실행 명령은 해당 커밋의 README와 이 문서에 기록한다.

## 완료 기록

- 기반 환경: Mac ARM64에서 Python 3.14.7과 잠금 의존성 설치 완료.
  PostgreSQL 18.6 별도 컨테이너의 read-only doctor 통과, 구성 검사 4개 통과.
  DSN query 자격증명 마스킹을 검토에서 보완했다. 회사 서버에는 접속하지 않았다.
- 데이터 계약: 시간대가 있는 이용 가능 시각/장 종료 시각, 원가격/조정가격, FX 방향,
  영구 종목 ID와 출처 선언을 저장한다. PostgreSQL 스키마 마이그레이션과 트랜잭션 수입,
  멱등 재수입 및 충돌 거부를 구현했다. 합성 데이터 생성기는 실제 시장 증거와 구분한다.
- 추천 계산: 시장별 12-1개월 신호, 진입/유지 순위 완충, 종목·업종·국가 상한과 비용 예약,
  정수 수량, 부족/노후화 가격·FX의 거부를 구현했다. 입력 snapshot은 변경하지 않는다.
  추천 ID에 데이터·코드·규칙·계좌·시각을 포함하고 결과 해시를 저장한다.
- 과거 시뮬레이션: 시간순 모의 체결, 원화 현금 원장, 납입 좌수 조정 TWR, 분할·배당
  권리와 지급, 국가별 별도 비교 계좌를 구현했다. 분할/배당과 같은 시각의 납입으로
  수익률이 왜곡되는 문제를 회귀 검사로 보완했다. 결과를 PostgreSQL에 변경 없이 보존한다.
  통합 검토에서 납입 시 중복 예약, 분할 직후 보류·재개, 계좌 시점과 기업행사 충돌,
  메모리 데이터 변경 방지를 보완했다. PostgreSQL 왕복 검사를 포함해 테스트 146개 통과.
- 개인 화면: 계좌 입력과 추천 생성·저장, 과거 시뮬레이션, 후보와 제외 이유, 원장·차트,
  데이터 출처와 과거 기록 조회를 연결했다. 미체결 추천과 모의 체결을 차트에서 구분한다.
  AppTest 6개, 차트 36개, DB 서비스 18개를 추가했고 전체 206개 통과.
  실제 localhost 브라우저에서 추천표·저장 이력·성과 그래프를 확인했다.
- 토스 시장 자료 수집: 공식 1.2.15의 공개 시장 GET 여섯 경로만 허용한다. 토큰을
  헤더로만 전달하고 원응답·수집 시각·계약 해시를 변경 없이 보존한다. 커서 반복과
  리다이렉트, 잘못된 응답·비밀값 반사를 차단했다. 계좌/주문/토큰 발급 기능은 없다.
  실제 인증 요청 없이 모의 전송·파일·CLI를 검증했다. 전체 테스트 306개 통과.
- 반복 검증: 개발·검증·예약 구간과 비용 1·2·3배의 아홉 조합을 동일 규칙으로 계산한다.
  요약과 상세 결과의 기간·비용·자금·지표 연결을 저장과 조회 양쪽에서 검사한다.
  소수 계산 환경을 고정하고, 미래 수익 우위나 실제 미열람 구간의 증명으로 해석하지 않는다.
  전체 테스트 400개와 PostgreSQL 저장·조회·마이그레이션 일치 검사를 통과했다.
- 종목 수 확대: Bundle별 참조 인덱스와 필요한 종목만 읽는 조회를 구현했다. 데이터
  내용 해시·공개 시점·기존 손익 계산을 보존한다. 신규 회귀 검사 35개와 1,000종목 합성
  벤치마크를 통과했고, 전체 데모 백테스트의 일별 곡선·체결·원장도 이전 결과와 일치했다.
  측정 작업과 한계는 `docs/PERFORMANCE.md`에 기록했다.
- 로컬 운영: 별도 앱 컨테이너, 구성 요소별 DB 설정, 잠금 의존성과 기반 이미지 digest,
  비특권 사용자·localhost 노출·자원 제한을 적용했다. Mac/Linux ARM64 추천·백테스트·평가
  JSON 전체가 일치했고, 로컬 에뮬레이션 Linux AMD64에서도 평가 전체가 일치했다.
  실제 8개 테이블을 일관된 snapshot으로 백업하고 새 DB에서 행·스키마·인덱스·revision을
  대조했다. 첫 검사에서 공유 catalog의 DB 표식 조회를 잘못 사용한 문제를 찾아 수정했고,
  수정 후 복원과 임시 DB 정리를 모두 통과했다. 원본과 성공·실패 기록은 보존했다.
  최종 검토에서 통합 테스트 URL query와 libpq 환경 변수가 접속 대상을 바꿀 수 있는
  경로도 차단했다. 마지막 전체 검사에서 PostgreSQL 통합 검사를 포함한 테스트 590개와
  Ruff 검사가 통과했다.
