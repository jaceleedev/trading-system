# Codex 조사 실행과 상황별 재판단

기능 20은 기존 Codex CLI를 별도 Python worker에서 실행한다. 조사 목적·선택 계좌·시장
캡처·연구 근거·이전 결과를 입력 시점에 고정하고, 출력과 실제 로컬 실행 관측을 구분해
보존한다. 새로운 모델 API 서비스나 유료 데이터 계약은 추가하지 않는다. 실제 주문은 없다.

## 실행

로컬 DB migration과 웹 빌드는 [작업 실행 안내](JOBS.md)를 따른다. 웹 API는 `--jobs`로
실행하고 ‘AI 조사’에서 목적을 입력한다. 계좌 관측은 상단에서 명시적으로 선택하고,
시장 캡처·연구 근거·관심 종목은 선택 사항이다. API 요청 자체는 모델을 시작하지 않는다.

```bash
mise run web-jobs
uv run trading-worker --allow-codex
```

`--allow-codex`는 저장된 ChatGPT 로그인으로 Codex를 실행하고 공개 웹 조사를 허용한다.
토스 GET 수집은 별도의 `--allow-network` 옵션이 필요하다. 두 옵션을 함께 켜면 모델이
요청한 추가 계좌·시장 자료 수집과 재조사가 이어진다. 기본 worker는 둘 다 실행하지 않는다.
현재 Mac에서 검증하며 원격 호스트나 launchd 상시 서비스는 설치하지 않는다.

`--codex-model`과 `--codex-reasoning-effort`는 신뢰하는 운영자 CLI 설정이다. 생략하면
Codex CLI의 내장 기본값을 사용한다. 현재 대화의 모델·추론 설정을 자동 상속한다고
표시하지 않는다. `--codex-timeout`은 한 프로세스의 기술적 시간 상한이며 기본 300초다.
`--once`는 조건 점검 한 번과 최대 한 작업을 수행한다.

```bash
uv run trading investigations create --input /path/to/request.json
uv run trading investigations list
uv run trading investigations show --id <조사-UUID>
uv run trading investigations revise --id <조사-UUID> --input /path/to/revision.json
uv run trading investigations pause --id <조사-UUID> --expected-revision 1
uv run trading investigations tick
```

요청 파일의 기본 형식은 다음과 같다. ID는 실제 저장 자료에서 선택한다.

```json
{
  "purpose": "현재 근거를 비교하고 다음에 확인할 기회를 조사한다",
  "mode": "prospective",
  "snapshot_id": null,
  "capture_ids": [],
  "evidence_ids": [],
  "symbols": [],
  "request_key": "investigation-first"
}
```

재검토 요청은 같은 형식에 `expected_revision`을 더하고 새 요청 키를 사용한다. 같은
요청의 응답이 유실되면 원래 키와 입력을 그대로 재전송한다. 서버가 새로 만든 시각과
입력 해시가 달라도 같은 논리 요청을 중복 실행하지 않는다. 합성 작업실은 `synthetic`
모드만 접수하며, 전향적·회고적·합성 기록을 서로 바꾸지 않는다.

## 판단과 실행 기록

모델 출력에는 요약·기회별 행동과 근거·반대 근거·불확실성·대안·재검토 조건·추가 자료
요청이 있다. 특정 규모·추세·정보 종류·보유 기간을 강제하지 않는다. 수익성이나 손실이
거의 없다는 전제는 검증된 사실로 취급하지 않는다. 자금 계산·체결은 후속 기능이다.

`source_findings`는 모델이 제시한 HTTPS 출처·제목·주장·발표 시각이다. 실제 웹 검색
횟수와 별개이며 페이지를 독립적으로 검증·저장한 근거로 승격하지 않는다. `evidence_ids`는
고정 입력에 실제 포함된 근거 ID만 허용한다. 외부 내용과 이전 모델 출력은 명령이 아닌 자료다.

실행 기록은 시작·종료, CLI 버전, 프로세스 종료 코드, JSONL 완료 이벤트, 사용량,
입력·출력·스키마·이벤트 스트림 해시를 포함한다. 모델 요청 설정과 실행이 보고한 정보는
분리한다. 현재 프로토콜에서 실제 모델 이름은 확인되지 않아 `reported_model=null`,
`model_identity_verified=false`다. 로컬 해시와 실행 관측은 원천 사실이나 모델의
암호학적 신원 증명이 아니다. 호출자가 전달한 JSON을 실행 증거로 접수하는 API는 없다.

## 고정 입력과 자료 범위

입력은 `var/investigations`에 비공개 내용 해시 객체로 저장한다. 같은 저장소에 출력과
성공·실패 실행 기록을 보존한다. `process_completed`는 모델 프로세스 완료를 뜻하며,
최신 결과 채택은 PostgreSQL revision과 작업의 성공 상태를 함께 확인해야 한다.
임대가 만료되거나 새 버전으로 교체된 실행의 파일은 남아도 최신 결과로 채택하지 않는다.

선택 계좌, 최대 50개 관련 모드 연구 기록, 명시한 근거 최대 100개, 캡처 최대 100개를
동결한다. 분봉·일봉은 300개 관측과 최대 20개 사건을 함께 제공한다. 그 밖의 허용된
시장 GET 응답은 최대 8 KiB의 미정규화 JSON 발췌와 원문 크기·해시·생략 여부로 구분한다. 완전한 원문은 원래 캡처 ID로 보존한다. 이후 시각 자료는 제외·거부하며 출처
파일을 재검증한다. 입력 2 MiB, 모델 출력·로그 크기와 깊이 상한을 넘으면 범위를 줄여야 한다.

계좌의 매수 가능 금액을 현금으로 바꾸거나 통화를 자동 합산하지 않는다. 새 계좌 수집은
선택한 스냅샷의 계좌 순번만 요청할 수 있다. 다른 계좌·임의 URL·명령·자격증명을 받지 않는다.

## 상황별 후속 조사와 중지

모델은 다음 재검토 시각, 종목별 새 시장 관측·근거 조건, 최대 10개의 읽기 전용 수집
요청을 제안한다. 수집 작업을 중복 없이 접수하고 성공·실패 결과를 다음 입력에 남긴다.
조회 실패를 자료가 없는 것으로 해석하지 않는다. 시각 조건은 입력 시각보다 뒤여야 한다.

상시 worker의 조정 스레드는 5초마다 로컬 조건을 확인한다. 이 값은 시장 수집 주기,
AI 판단 주기, 보유 기간이 아니다. 새로운 관측과 조건이 충족될 때 새 조사 버전을
접수하며 이전 실행·후속 수집에는 취소를 요청한다. 모델 실행 중에도 새 근거에 대응한다.

일시 정지는 버전 확인 후 현재 실행과 후속 수집을 함께 취소한다. 자동 조건 점검이
정지한 조사를 다시 켜지 않으며, 명시적 재검토로 재개한다. 최종 실패·작업 취소 후에도
명시적 재검토가 필요하다. `active`는 재검토 허용 상태이며 실제 실행 중이라는 뜻이 아니다.
화면에서 현재 작업, 이전 버전의 완료 결과, 현재 버전의 후속 수집을 각각 확인한다.

조건 점검은 최근 조사 100개와 예약 도래 조사 최대 20개를 다룬다. 대규모 조사 운영과
종목별 가격 임계값·뉴스 스트리밍 감지는 후속 확장이다. 현재 사건 조건은 새 저장 관측의
존재를 감지하고 세부 투자 의미는 AI가 재판단한다. 과거 관측으로 모델의 과거 지식을 재현하지 않는다.

## 프로세스와 복구

임시 작업 경로, 읽기 전용 sandbox, 승인 요청 없음, 사용자 설정·규칙 무시, 제한된 환경으로
Codex를 시작한다. 기존 ChatGPT 인증만 재사용하고 제공자 비밀값과 API 키 환경은 넘기지
않는다. 셸·앱·MCP 플러그인·컴퓨터 제어·추가 agent 실행은 비활성으로 지정한다.
공개 웹 검색만 조사 설정에 따라 허용한다. 실제 사용 명령은 로컬 CLI 도움말로 검증했다.

취소·시간/출력 제한·임대 상실 때 실행 그룹을 종료하고 회수한다. 부모 worker가 강제
종료되면 supervisor가 연결 종료를 감지해 자식 실행 그룹을 정리한다. 강제 종료 시
이미 기록한 파일이나 임시 디렉터리가 남을 수 있다. 재시작 복구는 작업 임대와 revision
검사에 따른다. 이미 실행한 외부 검색을 취소하거나 사용량을 되돌린다는 의미는 아니다.

조사 DB 이력은 PostgreSQL 백업에, 입력·출력·실행 파일은 [개인 자료 백업](ARTIFACT_BACKUP.md)에
포함한다. 파일 백업만 복원해서 작업을 자동 재개하지 않는다. 새 경로는 다른 작업 namespace다.

설정 참고: [Codex 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference).
실제 구현의 검증 결과와 제한은 [인수인계](HANDOFF.md)를 따른다.
