# 자금 계획과 대안 비교

기능 21은 저장 판단 또는 완료된 AI 조사 결과에 계좌 관측과 명시적 자금 가정을 연결한다.
신규·추가 매수, 유지, 축소·매도와 여러 항목으로 된 교체 대안을 계산한다. 모델의 현재
조사 출력에는 수량·가격·비용 구조가 없어 이 단계에서는 사용자가 가정을 입력한다.
AI의 구조화된 자금 제안과 운용 흐름 연결은 기능 25의 범위다.

각 대안은 독립적으로 비교한다. 한 대안 안의 매수 비용과 매도 수량은 합산하지만 아직
체결되지 않은 매도의 예상 대금은 같은 대안의 매수 여력에 더하지 않는다. 수수료·세금·
가격은 입력한 가정이다. 증권사의 확정 비용이나 주문 가능 여부를 인증하지 않는다.

## 금액의 의미

- 계획 여력은 관측한 통화별 매수 가능 금액과 명시한 계획 한도 중 작은 값에서 남겨둘
  금액을 뺀 값이다. 이미 다른 계획에 배정한 자금을 추가로 차감한다.
- 매수 가능 금액은 현금 잔고가 아니다. KRW와 USD를 합산하거나 자동 환전하지 않는다.
  계획 한도나 예약 상태를 모르면 결과도 미확인이다. 확인하지 않은 값을 0원으로 채우지 않는다.
- 추가 매수 후 예상 보유량·평균 매입가는 가정이며 실제 계좌에 쓰지 않는다. 한 대안에서
  같은 종목을 사고팔면 순서가 정해지지 않아 이후 평균 매입가는 미확인으로 둔다.
- 기존 진행 중 주문은 관측 범위와 매수 가능 금액에 이미 반영됐는지 알 수 없어 이중
  차감하지 않는다. 현재 자료로는 실제 주문 전송 준비가 완료되지 않는다.
- 고정 정밀도 256자리의 Decimal로 계산하고 정확한 십진 문자열을 저장·전달한다.
  나누어떨어지지 않는 평균가는 반올림 사실을 표시한다.

## 화면과 실행

웹 서버를 `--jobs`로 실행하면 로컬 DB의 계획 등록과 자금 배정을 사용할 수 있다.
계좌 관측을 명시적으로 선택한 뒤 ‘자금 계획’을 연다. 판단·조사 결과, 통화별 한도와
남겨둘 금액, 대안별 수량·가격·비용을 입력해 계산하고 저장한다. ‘선택 관측으로 계획 예산
적용’ 후 저장된 대안 하나에 자금을 배정하고 필요하면 해제한다.

배정은 작업실의 계획 기록이다. 증권사에 돈을 예약하거나 주문을 전송하지 않는다.
동일 계좌의 새 관측을 적용하거나 새 계획을 만들어도 이전 배정은 사라지지 않는다.
매도 수량도 기존 보유 자원에 배정한다. 두 요청이 동시에 같은 자원을 사용하려 하면
DB 트랜잭션과 버전 검사로 중복 배정을 막는다. 배정 합계가 새 여력보다 커지면 표시하고
기존 배정을 임의로 해제하지 않는다. 사후 분석은 현재 자원을 배정할 수 없다.

새 배정은 가장 오래된 계좌 관측이 15분 이내여야 한다. 이는 오래된 잔고로 자원을
배정하지 않기 위한 개발 단계의 검사이며 관측·AI 재판단 주기나 보유 기간을 정하지 않는다.
응답 유실 때는 원래 요청 키와 본문으로 결과를 재확인한다. 재전송이 새 계획·배정을
만들지 않는다. 계좌 선택을 바꾸면 이전 요청의 늦은 응답을 새 선택의 결과로 쓰지 않는다.

CLI도 같은 서비스를 사용한다. 요청은 비밀정보 없는 JSON 파일로 전달한다.

```bash
uv run trading capital preview --workspace /path/to/workspace --input plan.json
uv run trading capital create --workspace /path/to/workspace --input create-plan.json
uv run trading capital funding --workspace /path/to/workspace --account-seq 101 --snapshot-id <ID>
uv run trading capital refresh --workspace /path/to/workspace --input refresh.json
uv run trading capital reserve --workspace /path/to/workspace --id <PLAN_ID> --input reserve.json
uv run trading capital release --workspace /path/to/workspace --id <RESERVATION_ID>
```

`create`는 계산 요청에 `request_key`를 더한다. `refresh`는 `snapshot_id`, `mode`,
`funding`, `expected_pool_revisions`를, `reserve`는 `alternative_id`, `request_key`,
`expected_pool_revisions`를 받는다. 새 자원의 버전 0까지 포함한 맵은 `funding` 조회의
`snapshot-id` 옵션으로 가져온다. 웹 OpenAPI와 생성 SDK에 전체 타입이 있다.
`preview/show/list --offline`은 DB에 접속하지 않으며 기존 배정은 미확인으로 계산한다.
독립된 합성 작업실에는 CLI와 웹 모두 `--synthetic`을 명시한다. 일반 작업실은 합성
자원의 배정을 허용하지 않는다. 표시 설정은 계좌 관측의 진실성을 인증하지 않는다.

## 기록과 복구

계획은 `var/capital-plans/<sha256>.json`에 원래 계좌·판단/조사 참조, 예약 관측, 가정,
계산 결과와 시각을 고정한다. 읽을 때 출처와 입력을 검증하고 다시 계산한다. 같은 계좌의
새 관측으로도 기존 판단을 사용할 수 있지만 다른 계좌를 대신 연결하지 않는다.
조사에 계좌가 없었다면 계획 단계에서 명시적으로 선택할 수 있다.

PostgreSQL의 migration `b721fd9038a1`은 계획 요청 등록과 자원·배정 테이블을 추가한다.
파일만 복원해도 계획을 읽고 검증할 수 있지만 살아 있는 배정 상태와 요청 등록을 복원한
것은 아니다. 개인 자료 백업 v3는 계획 파일과 전체 입력 참조를 보존한다. DB 백업은
[별도 절차](LOCAL_BACKUP.md)를 따른다. 등록 경쟁 중 남은 유효한 계획 파일도 백업하되,
DB를 사용하는 웹 목록에는 등록된 계획만 표시한다.
