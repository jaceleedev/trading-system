# AI와 함께하는 개인 투자 연구 시스템

이 Codex의 AI가 실제 계좌와 다양한 자료를 읽고, 투자 기회를 조사하고, 대안을 비교해
판단과 재검토를 이어가는 개인 투자 작업 공간이다. 특정 투자 스타일이나 가격 방향으로
판단을 고정하지 않는다. 모델이 바뀌어도 근거와 결정 이력을 인계한다.

실제 토스 인증·시장 조회·계좌 스냅샷 수집은 확인했다. 추천·백테스트의 기본 자료는
여전히 합성 자료이며 전략의 실제 수익성은 검증되지 않았다. 주문 전송 기능은 없다.
현재 AI 사용 흐름과 명령은 [AI 작업 공간](docs/AI_WORKSPACE.md)에 정리했다.
[Codex 투자 도구](docs/CODEX_TOOLS.md)를 연결하면 이 프로젝트의 계좌 조회와 연구 기록을
Codex에서 직접 사용할 수 있다.

2026-09-10까지의 브랜치별 작업과 재시작 순서는 [인수인계](docs/HANDOFF.md)에 정리했다.

## 로컬 실행

Python 3.14.7, uv, Docker Compose가 필요하다. Python 버전은 프로젝트의 mise 설정으로 고정하며 전역 설정을 변경하지 않는다.

```bash
mise trust
mise install
uv sync --frozen
docker compose up -d --wait postgres
uv run trading doctor
uv run trading db-upgrade
mise run check
```

로컬 DB는 별도 `trading-research` Compose 프로젝트의 `127.0.0.1:55432`에서 실행된다.
회사 서비스의 `DATABASE_URL`은 읽지 않는다. 명시적 변경은 `TRADING_DATABASE_URL`로 지정한다.
또는 `TRADING_DATABASE_HOST`, `PORT`, `NAME`, `USER`, `PASSWORD` 다섯 구성 요소를
모두 설정한다(각 변수에 `TRADING_DATABASE_` 접두사). URL을 명시하면 URL이 우선한다.
Compose의 기본 비밀번호는 로컬 개발 전용이다. 실제 서버 배포 설정은 별도로 작성·검토해야 한다.
Compose의 포트·비밀번호를 변경하면 앱의 `TRADING_DATABASE_URL`도 같은 값으로 명시해야 한다.
DB를 중지하려면 `docker compose stop`을 사용한다. `down -v`는 자료를 삭제하므로 일반 종료에 사용하지 않는다.

## 데이터 가져오기

개인 화면은 `mise run ui`로 시작하고 <http://127.0.0.1:8501>에서 연다.
첫 화면 ‘AI 투자 작업실’은 저장한 실제 계좌 관측과 조사·판단·재검토 이력을 읽는다.
이 화면만 사용할 때는 DB나 합성 데모를 먼저 준비할 필요가 없다.
[화면 사용법](docs/USER_GUIDE.md)에서 추천·성과·출처·기록 조회 흐름을 확인할 수 있다.
Docker 화면은 <http://127.0.0.1:8502>를 사용한다. 처음 실행과 이미지 갱신,
상태 확인·백업·복구 명령은 [운영 안내](docs/OPERATIONS.md)에 정리했다.

```bash
uv run trading demo-data var/demo
uv run trading validate-data var/demo
uv run trading import-data var/demo
TRADING_TEST_DB=1 uv run pytest
```

데모는 실제 종목이나 성과가 아닌 합성 자료다. 새 폴더에서만 생성되며 기존 파일을 덮어쓰지 않는다.
실제 자료는 [입력 계약](docs/DATA_CONTRACT.md)에 맞는 공급자 CSV와 manifest를 준비한다.
검증은 시각·가격·OHLC·중복·출처 선언을 검사하며, 공급자 자료의 진실성까지 인증하지 않는다.
동일 자료 재수입은 변경 없이 종료하고, 같은 ID에 다른 내용을 덮어쓰는 요청은 거부한다.

토스증권의 읽기 전용 시장 자료 수집기는 [수집 안내](docs/TOSS_CAPTURE.md)를 따른다.
발급받은 Client ID·Secret은 [토스 인증 안내](docs/TOSS_AUTH.md)에 따라 Mac 키체인에
설정한다. API 원응답 보존과 추천용 데이터 검증을 구분한다. 주문 기능은 없다.
[계좌 조회 안내](docs/TOSS_ACCOUNT.md)의 `trading toss-account`로 계좌를 명시적으로 선택해
보유 주식·매수 가능 금액·수수료·진행 중 주문을 조회하고 비공개 로컬 스냅샷을 저장한다.

## 추천 생성

```bash
uv run trading recommend --dataset synthetic-demo-v1 \
  --as-of 2026-08-31T23:00:00+00:00 --account configs/account.demo.json --save
```

계좌 파일은 당시 확정된 원화 현금·보유 수량을 입력한다. 예정 납입은 현금에 더하지 않는다.
판단 시각보다 미래이거나 24시간보다 오래된 계좌 입력은 거부한다. 제공 예시는 합성 시연용이다.
추천에는 데이터·코드·규칙·계좌·시간과 후보/제외 이유가 기록된다. `--save`는 추천 이력만
저장하며 보유량이나 실제 주문을 변경하지 않는다. 상세 [첫 검증 규칙](docs/RESEARCH_RULES.md)을
확인한다. 저장 가능한 결과가 나와도 실제 시세나 전략 수익성이 검증된 것은 아니다.

## 백테스트

과거 시뮬레이션은 [백테스트 실행 및 회계 계약](docs/BACKTEST.md)을 따른다.
납입금과 손익을 구분하며 분할·배당·비용을 원장에 기록한다. 합성 결과는 성과 근거가 아니다.

고정한 세 기간·세 비용 가정을 모두 비교하는 `trading evaluate`와 화면 ‘반복 검증’은
[검증 계획](docs/EVALUATION.md)을 따른다. 좋은 결과만 골라 전략을 선택하지 않는다.

개발용 `mise run benchmark`는 [처리 속도 측정](docs/PERFORMANCE.md)에 따라 합성 자료에서
이전 조회 방식과 계산 결과를 비교한 뒤 시간을 측정한다. 투자 성과 검증과는 별개다.

## 투자 범위

- 개인 주식투자 추가 납입: 월 500,000원. 급여일은 매월 10일이며 다음 납입은 2026-09-10 예정.
- 연금 월 500,000원은 이번 연구에서 제외한다. 연금 해약을 투자 재원으로 가정하지 않는다.
- 연구 대상: 국내·미국 주식 모두. 현재 이용 증권사는 토스증권·삼성증권이며, 기능상 이점이 있다면 다른 증권사 이용도 가능하다.
- 사용자 제공 현황(2026-09-09): 총자산 약 750,000원으로 해석하며 한전기술 1주와 현금 보유. 매수가 149,000원, 제시한 주가 139,500원. 실시간 계좌·시세 조회 결과는 아니다.
- 위 금액이 주식을 포함한 총평가액이면 현금은 약 610,500원이다. 다음 납입 후 총평가액 약 1,250,000원·현금 약 1,110,500원을 계획값으로 사용한다. 주가 변화·비용은 제외했고 납입 완료는 미확인이다.
- 사용자는 개인투자 원금 전액의 손실을 감수할 의향을 밝혔다. 구체적인 운용 중단 기준과 종목별 위험 한도는 별도로 정하며, 차입이나 주문의 승인을 뜻하지 않는다. 목표 기한은 미확정이다.
- 장기 목표 1,000억 원과 중간 목표 1,000만 원 → 3,000만 원 → 1억 원은 희망 목표다. 달성 전망이나 확정 수익률이 아니다.

## 현재 판단

1. AI가 필요한 정보와 분석 방식을 선택해 투자 가설·대안·반대 근거를 검토한다.
2. 대형주·중소형주, 상승·하락, 거시·기업·차트 중 한 가지 접근을 고정하지 않는다.
3. 기존 `momentum-v1`과 지수 비교 기능은 판단을 평가하는 도구로 활용한다.
4. 모든 판단에 계좌·근거·작성 시각·모델 선언·재검토 조건을 연결하며 결과를 덮어쓰지 않는다.
5. 주계좌 연동은 토스로 진행한다. 실제 읽기 전용 연결은 확인했고, 추가 증권사 연동은
   필요한 기능상의 이유가 생길 때 검토한다. 삼성 계좌의 이관·해지는 수행하지 않았다.
